# AI 漫剧：剧本、分镜脚本与视频提示词模板

整理日期：2026-10-23。依据用户提供的桌面 `prompt` 文件夹中的 `seedance.md`、`Wan3.md`、`H3.md`。这里只整理模板，不安装 Skill，也不改变视频提交接口、模式、时长、比例、素材角色或轮询流程。

**现行生成格式（2026-11-07）**：通用稿、Seedance、Wan3、H3 的默认画布稿和普通文本稿一律按 `【固定资产】→【视频生成风格类型】→【分镜】` 排列。先列本段实际图片及人物、场景、关键道具用途，再写 3D CG / 2.5D CG 等已定画风、画幅、节奏、影调和“人物按照参考图生成”，最后写连续时间轴分镜及对白、声音、状态交接。视频必须先有真实图片参考，缺人物或场景图时先生成并复用参考图；不以纯文字直接出片。下方旧四段式、H3 六字段和纯文生示例保留为 2026-10-23 来源资料，**不得直接复制到当前画布或视频生成请求**；H3 六字段仅在用户明确要求原生协议导出时使用。当前可执行模板以 `G:/skillplugins/skills/剧本转提示词` 为准。

## 先交剧本，再按剧本拆分镜

本节是 AI 漫剧的创作与交付约定；后面的引擎模板只用于最后的提示词适配。AI 漫剧的分镜描述可连续表演的视频：人物有动作、对白与反应，镜头有时长和衔接。

**执行方式：纯 Markdown Skill，由大模型直接创作和自查。** 读取题材、项目设定与本节规则即可写出剧本和分镜；不需要 Python、校验脚本、命令行、第三方插件或 API 调用。文件是创作规则、模板和交付正文，不是调用工具生成内容的入口。需要视频提示词时，也由大模型根据分镜写成文字，不自动提交生成。

```text
题材 / 小说 / 分集大纲
  → 剧本.md：这一集发生什么、谁做什么、谁说什么
  → 分镜脚本.md：把同一份剧本逐场拆成可拍的镜头
  → 可选：各段引擎提示词
```

用户要求“先出剧本再拆分镜”时，交付前两份完整正文。简报、故事梗概、资产表、路由计划、镜头提示词均不能替代它们。先完成本批剧本并自查，再基于该版本拆镜；无需默认再等一次“继续”。用户要求审核剧本后再拆镜时，遵守该停点。

| 用户提供的内容      | 应完成的工作                                                                     |
| ------------------- | -------------------------------------------------------------------------------- |
| 一句话题材或大纲    | 在用户指定范围内写成完整剧本，再拆分镜；新创作内容可以补全，明确采用的创作假设   |
| 小说原文            | 按用户改编权限写剧本，保留关键因果和受保护对白，再拆分镜                         |
| 已有剧本            | 直接以该剧本为依据拆镜；缺场景号可在分镜中用原场次标题与原句定位，不擅自重写正文 |
| 只要剧本 / 只要分镜 | 只交指定产物；只要分镜却没有剧本时，先指出缺少的输入，不能把新编剧情冒充原文     |

读取已提供的项目简报、上文和剧本，复用集数、单集时长、画幅、风格、角色设定、段长、节奏和必须保留的内容。只做一集或样片时，不把全季大纲、全部素材上传和引擎选择作为写剧本的前置条件。不能从现有材料确定的创作项标为假设或待定；精确时长、明确画幅和资产锁定仍是相应生产档位的验收条件，未满足时交付状态应写“草稿”，不能虚报可直接生产。

### 两份正文分别包含什么

**剧本**：集名与本集目标；按顺序排列的场景号、内外景、地点、时段、出场人物；可见动作；带发声者和表演语气的逐句对白；与动作对应的声音；本集结果或悬念。摄影机运动、景别、模型方言放到后续层。

**分镜脚本**：剧本依据版本、全片时长/画幅与段长；每镜来源、时间段及持续时长、人物/场景/道具/造型、景别/机位/主运镜、起始状态→动作与反应→结束状态、发声者/原台词/口型或画外音、环境与同步声音、转场及下一镜承接。末尾附本批来源覆盖核对。

本地 `G:/skillplugins` 体系已有专用格式，实际生产继续使用：

- `manju/manju-director/SKILL.md`：协调本批剧本与分镜交付。
- `manju/manju-script/SKILL.md` 与 `templates/剧本输出模板.md`：剧本正文及场景编号。
- `manju/manju-storyboard/SKILL.md` 与其 15/30 秒模板：分镜正文及段内时间轴。

上述路径相对于该本地资料库；Canvas 不会自动加载或安装它们。本节示例是解释两份产物的阅读方式，不替换这些模板的正文格式。

### 从桌面 prompt 文档吸收的写作规则

2026-10-23 重新核读本地 `seedance.md`、`Wan3.md`、`H3.md`，把共通的导演表达用于分镜，模型专用语法留在最后的可选适配阶段：

- **明确素材只参考什么**：形象、服装、动作、运镜、场景、音色各有来源。只有图片时不能声称已有声音参考；只借音色时不复制参考音频原台词。没有素材时用剧本角色名与文字设定，不编造“图1/音频1”。
- **把说话与表演分开**：`角色（语气）：原台词`；表演、视线、停顿写在引号外，不在台词后反复复述词语。多人镜头说明本句由谁发声、其余人如何反应；只有原剧本要求齐声时才多人同步说话。
- **给动作明确的过程**：谁从什么姿态开始、做了什么、造成什么可见结果；运镜另写主方向、幅度和速度。固定机位与移动机位不能同时成立，分阶段变化须写清。
- **声音随事件落点**：环境音可连续铺底，动作音对应接触瞬间，配乐依剧情需要变化，不覆盖对白；“无台词/无配乐”只在该镜确实不需要时写，不作为全篇默认禁项。
- **连续时间轴优先**：Wan3 正文要求镜头首尾相接；其个别示例的 `0–3 / 4–6 / 7–10 秒` 存在空档，不照抄。按故事需要重新排满时间；过载内容拆镜，不靠高频动作或加速念词。
- **仅保留实际相关约束**：用具体的人物、持物、方向与状态减少穿帮；不堆无关负向词，不把参考案例的画风、人物或结局带入新剧本。无字幕等提示只能降低生成风险，不承诺必然实现。

H3 的六部分英文格式、`<Subject N>` 与 `(Sx)` 是引擎适配约定。中文剧本和分镜只需明确人物、发声者与来源，不必提前改成英文、加入这些标签或改变原对白。

### 从剧本拆镜的约束

1. **先定位来源**：记录输入剧本的文件及版本；逐镜指向原场景号、动作原句与对白原句。没有逐句 ID 时，用“场景号＋该场第几条对白＋原文”定位，不创造已存在 ID 的假象。
2. **按叙事需要切镜**：动作发起、对方反应、关键信息揭示、空间变化可以切镜。只补拍摄表达，不增加原文没有的动机、结果、人物或反转。反应镜可承接同一句画外音。
3. **完整保留对白**：长句可以按原文顺序跨镜分配，标清同一句的前半/续接，拼接后必须与原文一致；不可重复播放整句，也不可漏字。保护说话者、原语言、标点和语义。
4. **先算可说完，再排镜**：预留动作、停顿、呼吸和反应时间。无录音时只给估时；录音到位后复核。原台词与固定时长冲突时，报告具体超载位置及拆段方案，不默认删词、加速或更改用户时长。
5. **连续性逐镜接续**：人物站位、视线、持物手、道具归属、服装/伤势、运动方向和声音保持连续；改变须有可见动作或原文依据。姿态保持不等于冻结画面。
6. **覆盖核对**：逐场列出动作、对白和关键声音对应的镜头；有意留在画外的事件也说明呈现方式。未覆盖项明确列出，不以“全部完成”掩盖删漏。剧本更改后重新核对受影响镜头和上下镜承接，不沿用旧版通过结论。

**三个时间单位分开**：镜头是一次连续拍摄表达；15/30 秒段是本地分镜生产档位，一个段可包含多镜；单次生成请求受实际引擎能力限制，可以覆盖一镜或多镜。分段不是剧情换场，不能每到段尾就另编悬念。若引擎容不下该段，另列生成拆条与剪辑接点，不改剧本事实。全片时间累计连续，段内时间可以从 0 重起；两种时间不要混用。

### 贯通示例：同一场戏如何拆成镜头

以下为虚构教学片段，设定为 15 秒、16:9、对白节奏；不是一集完整剧本，也不表示已经录音或试生成。正式交付须完成用户要求的全部场次，不能只交这段示例。

**第一份：剧本片段**

```text
EP001-SC001 内 · 旧书铺 · 夜
人物：沈砚、阿宁。
△ 沈砚在桌左，左手托着打开的账本；阿宁在桌右，右手扶着桌沿。
△ 阿宁盯着账页。沈砚抬眼看她，右手翻过一页。
阿宁（压低声音）：这页账，是谁改的？
沈砚（平静）：先看落款。
△ 阿宁低头看向落款，右手仍扶桌沿；沈砚右手停在翻开的页边。
声音：窗外细雨；翻页时纸张轻响。
```

**第二份：对应分镜片段**（段内时间，累计 15 秒）

| 镜头 / 来源                  | 时间           | 画面与动作过程                                                                 | 台词与声音                                         | 结束状态 / 承接                                    |
| ---------------------------- | -------------- | ------------------------------------------------------------------------------ | -------------------------------------------------- | -------------------------------------------------- |
| 1 / SC001 开场站位、阿宁问话 | 0–5 秒，5 秒   | 中景固定机位；沈砚在画左托书，阿宁在画右扶桌，视线落在账页；阿宁压低声音问话   | 阿宁：“这页账，是谁改的？”；细雨持续，不强加动作音 | 阿宁仍扶桌，沈砚左手托书；下一镜切沈砚，同一轴线   |
| 2 / SC001 抬眼、翻页、回答   | 5–10 秒，5 秒  | 沈砚近景，固定机位；从看账页到抬眼看阿宁，右手翻过一页并回答；阿宁留在画外桌右 | 沈砚：“先看落款。”；翻页瞬间纸声，细雨持续         | 右手停在页边，左手托书；账本不换手、不合上         |
| 3 / SC001 看落款、页边停手   | 10–15 秒，5 秒 | 阿宁侧面近景，账本在下方前景；她低头看向落款，右手仍扶桌；保留自然呼吸         | 无新增对白；细雨延续，翻页声已结束                 | 阿宁视线停在落款，沈砚持书状态延续；不编造落款内容 |

覆盖核对：问话→镜 1，抬眼/翻页/回答→镜 2，低头看落款/手停页边→镜 2–3；两句对白逐字保留，声音各有落点。可见文字若需要后期叠加，应另列制作说明，不让视频模型猜写，也不新增剧情答案。

## 30秒主流程、15秒兼容与三引擎适配

本轮结合12个GitHub创作项目的Skill与参考文档，更新本地纯Markdown规则。完整来源、许可与采用边界见 [研究索引](../../skillplugins/_dev/_research/github-2026-10-23/仓库与Skill索引.md)；只吸收创作方法，不引入上游程序依赖。

**默认30秒指分镜编辑段，不是整集长度，也不是三引擎共同的生成上限。** 用户指定15秒时保留15秒结构；完整30秒内容改成两段15秒时全部事件与台词仍须保留，第二段时间归零，但全片位置仍为15–30秒。75秒作品可以组织为30＋30＋15，不必修改剧情凑整除。

### 保留同稿，不只换模型名

- **节拍对应**：镜头指向原场次/动作/台词；一个节拍可以跨镜，跨镜对白片段按顺序拼回原文，不能重播或漏词。来源核对要给出落点，而非只说“已覆盖”。
- **动作差异**：打斗先定可见目标与人物擅长距离、移动和反制；逐拍交代发起、指向、防守或落空、接触结果、位移与新状态，不强制每秒动作数或每段逆转。
- **特效过程**：触发、形成、传播、接触、环境受光、消散与残留；残影、无碰撞投影与实体分开。粒子/闪白不能盖住关键接触，后镜继承伤势、资源和破坏。
- **拍摄表达**：固定机位可以拍动作，克制表演可以成立；不为了镜头配额强塞手势、运镜或无信息反应。当前采用稿与用户指定镜头优先。
- **适配保持**：三版的台词、说话人、事件顺序、实际段长和最终状态一致；变化仅在提示词结构、引用与声音语法以及确有依据的请求拆条。

### 请求能力与时间精度

### H3普通模式补充

为避免没有素材时虚构全参考标签，2026-10-23 另核读 [H3普通模式指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)。以下无素材 T2VA 三字段仅记录官方原生语法，不用于当前视频出片流程；缺参考图片时须先生成、绑定并复用：

```text
integrated_multimodal_description: [Shot 1] English visual description and actual speaker (S1): <d>[Chinese] 原台词</d> [Shot 2] At 00:05.000, ...
overall_soundscape: English ambience and physical sounds.
non_diegetic_music: English audience-only score, or N/A.
```

该时间戳仅示范语法，不是固定5秒镜长。已有真实首尾帧的I2VA/FL2VA/L2VA增加相应对齐句；多素材全参考继续使用后文六部分。H3的首镜不带时间戳，后续切点严格递增且在总长内；最后镜头描述到30或15秒终点，不以终点新建空镜头。

## 通用素材绑定

为后续 Skill 提供结构化素材清单，至少包含：引用 ID、资产 ID、冻结版本、媒体类型、用户明确命名、用户指定用途，以及当前实际发送顺序。素材内容未提供给 Skill 时，只能依据用户文字和已确认说明，不得声称看到了图片、听到了声音。

- 图片、视频、音频各自从 1 计数，以实际提交顺序为准。资源条的混合顺序号不等于模型类型编号。
- 画布内的内联引用要 `inline:true` 且不设 `executionOnly`（设了渲染为空串）；视频提示词正文写 `陈砚 `（名字＋一个空格，不写字面 `@`）再放 mention，编号由提交/预览层按实际发送顺序与模型族渲染，顺序与连线/挂载一致；素材引用与连线双写。
- 镜头块正文里人物/场景首次出现处同样挂引用（同一镜内同一素材只挂一次、跨镜可各自再挂）；台词行、`声音：<…>`、`环境：…`、`【镜头】`、`【时间】`、`【防穿帮约束】` 各行列不挂编号，`（）`、`“”`、`【】` 内部不挂。
- 同资产、同版本、同角色的重复引用复用编号；不要按出现次数生成新的素材。
- 同名文件不能合并，不同版本不能替换为最新版本。
- 别名用于显式绑定，不能仅凭文件名推断人物身份、衣服颜色、动作或音色。
- 当前提交层只把明确设置的 `entityName` 附在引用旁，例如 `图1（小明）`；视频提示词 v2 不建议设置它（名字已写在正文），也不自动生成素材说明、Subject 定义或整篇重写。完整用途绑定由用户或后续 Skill 明确表达。
- 一份素材可提供多个主体，一个主体可由多份素材共同定义。不要默认“一图一人”。
- 普通视频包含声音，不代表需要增加独立音频引用；只有明确独立输入或启用的音轨才能绑定音频。
- 只替换结构化引用，不全局替换用户文字中的“图1”、`Image1`、文件名、`<Subject 1>` 或台词。

## H3 全参考重写（仅明确要求原生协议导出）

来源：`H3.md` 的 Full-Reference Mode Rewrite Output Format Guide。此文件比中文博客更具体：要求六个部分为英文，保留台词、歌词和场景可见文字的原语言。以下中文说明是模板注释，真正重写时按要求输出英文。

四类编号有不同语义：

- `<Subject N>`：人物、物体、环境、服装、风格或动作等可复用内容，不是上传文件序号。
- `<Picture N>`：作为首帧、关键帧、尾帧、构图或故事板锚点的图片；若只提供外观，在 Subject 定义中引用它，不机械增加独立 Picture 定义。
- `<Video N>`：编辑源、延长源、运镜/剪辑/时序结构来源；从视频借用的人物或动作仍可属于 Subject。
- `<Audio N>`：复制或参考的音频信号。与视频分别计数，不暗示同号配对。

先按素材情况选模式：带参考素材的段落用 Ref2VA 六部分（`subject_definitions:` / `summary:` / `retention_analysis:` / `detailed_description:` / `overall_soundscape:` / `non_diegetic_music:`）；纯文生、无素材的段落用 T2VA 三字段（`integrated_multimodal_description:` / `overall_soundscape:` / `non_diegetic_music:`）；首帧、首尾帧或尾帧驱动分别用 I2VA / FL2VA / L2VA，并加官方对齐句。素材说明与视频类型在六部分中不单独成段：外观与用途进 `subject_definitions`，整体概述进 `summary`（以 `[reference generation]` 开头）；【防穿帮约束】不新增字段，改写成一句英文一致性要求并入 `detailed_description`，例如 `Keep hand anatomy, facial features, clothing and seat-floor contact consistent across shots; no floating, no limb distortion, no extra fingers.`

```text
subject_definitions:
<Subject 1> is the person identified by the user in <Picture 1>; preserve the user-specified appearance.
<Video 1> provides the camera movement and shot rhythm for the target video.
<Audio 1> is the voice-timbre reference for <Subject 1> (S1).

summary:
[reference generation] The target video follows <Subject 1> through the user-specified scene, referencing the camera movement of <Video 1> and the voice timbre of <Audio 1>.

retention_analysis:
<Subject 1> (appears in [Shot 1], [Shot 2]): fully_preserved - Preserve the defined appearance; the target action follows the user's request.
<Video 1> (camera movement and shot rhythm): weak_reference - Follow only the selected movement and rhythm, not its characters or background.
<Audio 1>: reference - Reference the voice timbre without copying its dialogue or original signal.

detailed_description:
The target video uses the user's specified visual style and lighting.
[Shot 1] Describe the visible composition, subject position, environment, action, state change, camera movement and current sound. <Subject 1> (S1) says, <d>[Chinese]这里保留用户提供的中文台词。</d>
[Shot 2] At 00:03.000, describe the next shot, continuity, action and active reference relationships.
Keep hand anatomy, facial features, clothing and seat-floor contact consistent across shots; no floating, no limb distortion, no extra fingers.

overall_soundscape:
Describe only the intended ambience and physical sounds, with their reference relationship when relevant.

non_diegetic_music:
Describe the intended audience-only background music and its progression, or explicitly state its absence when requested.
```

上例是结构骨架，不是可直接用于任意素材的完成稿。实际 Skill 必须依据用户材料重写，不可默认存在人物、视频、音频、对白或两个镜头。`fully_preserved` 等关系标记也须按用户明确的参考用途选择。

六部分之外不再增加“素材说明”“视频类型”“防穿帮约束”这类中文栏目：外观与用途已在 `subject_definitions`，整体概述与画风在 `summary`，一致性与防穿帮在 `detailed_description` 正文里写成英文句子。画布内写六部分时同样在正文写 `陈砚 `（名字＋一个空格，不写字面 `@`）再加内联 mention（`inline:true`、不设 `executionOnly`），`<Picture 1>`/`<Video 1>`/`<Audio 1>` 的编号由提交/预览层按实际发送顺序渲染，不手写；纯文本版写作 `月栖 <Picture 1>；绯檀 <Picture 2>`，同样不带 `@`。镜头块（或 `detailed_description` 的分镜叙述）里人物/场景第一次出现处也要挂引用，台词、声音与镜头行不挂。

视觉关系可选：`fully_preserved`、`partially_preserved`、`attribute_transfer`、`weak_reference`。音频关系可选：`fully_copy`、`partially_copy`、`reference`、`weak_reference`。仅借音色不等于复制整段声音；复制全部最终音轨才是 `fully_copy`。

说话者 `(S1)`、`(S2)` 按实际发声顺序全局分配，不按 Subject 编号分配。台词放在 `<d>[语言] 原台词</d>`；跨镜头、视频结束截断等特殊情况按原文使用 `<scenetrans>`、`<cutoff>`。不要在 retention_analysis 中写说话者 ID。

`detailed_description` 对生成任务通常建议 350–500 个英文词，但对白时间完整性优先，编辑任务按复杂度调整；不能把这个建议当作提交硬限制。正文应详细描述画面和声音，而不只是引用清单或剧情梗概。

## 多人剧情的镜头卡与连续性补充

来源：用户于 2026-10-23 提供的主播提示词局部截图。截图可见时间段、景别与运镜、角色资源引用、画面动作、台词、音效，以及“首帧／尾帧／段末可继承状态”等栏目。这些是可借鉴的创作组织方式，不是模型官方新增语法；截图不足以确认完整提示词、实际提交内容或生成效果。

### 值得保留的写法

- **角色与发声者明确对应**：先绑定角色的外观来源，再逐句标明谁说话、怎么说；多人同框时补充其他角色在做什么。角色图片只提供视觉参考，不能据此认定已有音色参考。
- **动作写出变化过程**：例如“抬眼看向对方，说完后重新低头看书”，比只写“冷静分析”更具体。微表情应与景别匹配；瞳孔变化等细节不适合作为中远景的主要动作要求。
- **每镜头有起始状态和结束状态**：记录站位、朝向、视线、手部、道具和动作进度。下一镜头承接这些状态，确有改变时写明转身、递物或切换机位等原因。
- **声音独立说明**：区分原语言台词、表演语气、环境音、动作音和 BGM。同步音效写清触发点，例如“手指翻过书页时响起轻微纸张声”。
- **给后续片段留下可延续状态**：镜头末尾记录角色位置、道具归属、动作是否完成，以及是否仍有台词、环境音或音乐。这份记录可作为下一段的输入；当前程序不会自动跨任务传递它。

### 建议改进的地方

- 将截图中的“时长 10–18 秒”明确写成“时间段 00:10–00:18（持续 8 秒）”。只写“18 秒”无法区分起点、终点或持续时长，多镜头应提供明确边界。
- 先核算台词、停顿与动作能否放进镜头。截图所示 8 秒片段包含较长对白，存在赶语速或截断风险，但不能仅凭截图判定实际效果。保留用户原台词，优先提出分镜或时长调整建议；未经确认不删词、不改请求时长、不默认加速。
- 将“防穿帮”写成固定清单加本镜特殊项，而不是只重复“规避穿帮”这一栏目名：固定清单写禁止多指、手指粘连、手部畸形，禁止人物穿模、肢体扭曲，禁止椅子与地砖接触关系错误、人物漂浮，禁止面部变形、五官不对称，禁止画面崩坏、镜头漂移；再加本镜实际相关的约束，例如“书始终由左手托住，右手翻页后回到书页边缘”。全段一致时可在段末统一写一次。
- “保持表情”与“冻结画面”分开表达。若只要角色保持怒视，可写“维持怒视，保留自然呼吸与细微动作”；只有用户需要静止帧时才使用“画面定格”。
- “手持＋轻微环绕”等组合要交代主运动、方向与幅度；“近景＋甩镜＋微定格”应说明先后阶段，避免把互相冲突的镜头状态写成同时发生。
- 此处“起始／结束状态”是文字中的画面状态，不代表新增首帧、尾帧图片输入，不改变生成模式或上传角色。
- 截图中的文件名标签是界面引用样式，不能据此认定模型收到文件名或 `@`。当前编辑器继续保存结构化引用，提交时按引擎替换；不照抄 `.jpeg` 名称作为可靠的模型绑定。

### 可选镜头卡模板

以下适合有对白、多人互动或连续剧情的镜头。简单单镜头可删减栏目，不必全部填满。`【】` 中的字段是文档中的待填说明，不是编辑器实际的资源占位符。

```text
【镜头N】
【时间】：【起点】–【终点】秒
【镜头】：【景别】，【焦距】，【机位/运镜】，【景深】，【视角】
【角色】 图N（【服装/造型】，【持物】）在【场景位置】 图M【起始状态】；【按时间顺序写动作、反应与可见的表情变化】，其他人物或场景首次出场时同样在名字后隔一个空格挂编号。
末态：【最终姿态、视线、持物、道具位置与动作完成度】。
【角色】（【语气、语速、停顿】）：“【用户原文】”
声音：<【环境音】><【动作音】>【需要时写 BGM】
【防穿帮约束】：禁止多指、手指粘连、手部畸形；禁止人物穿模、肢体扭曲；禁止椅子与地砖接触关系错误、人物漂浮；禁止面部变形、五官不对称；禁止画面崩坏、镜头漂移；【本镜特殊项，没有则省略】。
```

镜头卡里编号只挂两处：`【角色】` 与场景/道具名字之后（如 `【角色】 图1`、`【场景位置】 图2`），写法是「名字 + 一个空格 + 编号」，不带 `@`；同一镜内同一素材只挂一次。台词行、`声音：<…>`、`环境：…`、`【镜头】`、`【时间】`、`【防穿帮约束】` 各行列不挂编号，`（）`、`“”`、`【】` 内部也不挂。

例如，在“角色低头看书，随后抬眼回答”的既定剧情下，可以把正文写成：“左手托住打开的书，抬眼看向对方并说出原台词；说完后低头、右手停在书页边缘。末态：低头，右手停在书页边缘。下一镜头接同一持书姿态。”再补本镜防穿帮特殊项“书始终由左手托住、不悬空”。这是一条连续性示例，不应自动添加到其他剧情。

### 三个引擎如何使用

| 引擎     | 接入方式                                                                                                                                                                                                        |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Seedance | 将镜头卡放入分镜／时间轴部分；素材用途在开头明确绑定，各镜头按需引用，结尾补充实际相关的连续性要求。                                                                                                            |
| Wan3     | 使用连续时间段组织镜头卡，角色台词及声音跟随对应镜头；以图N、视频N、音频N表达具体来源，不重复堆叠负向要求。                                                                                                     |
| H3       | 在六部分结构中分配这些信息：身份来源进入 subject_definitions，镜头动作、起止状态与对白进入 detailed_description，整体声音进入对应声音部分；仍遵守英文重写、原语言台词及说话者编号规则，不另造一套强制中文栏目。 |

后续 Skill 可以检查时间段是否连续、台词是否有发声者、角色／道具是否无故换位，以及镜头结束状态是否能接到下一镜头。对缺少的创作信息给出待确认建议，不将猜测写成既定事实；这些检查属于文案质量检查，不是新的提交拦截条件。

## 后续 Skill 的输入输出约定

建议输入：目标引擎、用户原文、任务类型、已确认时长/画幅、结构化素材清单、用户明确的参考用途、原语言台词、必须保持的内容，以及素材是否实际可读。缺少的创作信息可给出建议，不能把猜测写成已知事实。

建议输出分开保存：

1. 可供用户预览的提示词草稿。
2. 素材用途与引用 ID 的绑定说明。
3. 尚待用户确认的歧义，不夹入最终生成正文。

接入当前优化器时，必须保留其原有资源占位符、顺序、数量及冻结身份。Skill 不手写画布编号，也不自行把占位符改成“图1”或重新编号：正文写 `陈砚 `（名字＋一个空格，不带字面 `@`）并在其后插入内联 mention（`inline:true`、不设 `executionOnly`，`entityName` 默认不设），编号由提交/预览层在最终媒体顺序确定后按模型族渲染（Seedance `图 1`、Wan3 `图1`、H3 `<Picture 1>`、未识别模型 `Image 1`），顺序与连线/挂载顺序一致。为表达重复指代或额外 Subject 定义需要新增引用时，先扩展并验证结构化引用合同，不能绕过现有校验硬拼字符串。

使用上述模板手写纯文本（不在画布内）时，由作者自行写编号并保证与素材一致；普通文本中的编号不会随资源条重排自动更新，需人工复核。画布内不适用这一条：正文不写数字，顺序由连线/挂载顺序决定，写完点「查看真实提示词」核对实际渲染结果。

本轮同步更新的只是文档与提示词文本（`apps/api/src/canvas-mcp.ts` 的 MCP 说明、`apply_canvas_operations` 的工具说明、内置「漫剧导演」Skill 指令与本文件）；`promptDocument` 字段、mention 渲染、编号生成与提交路径均未改动，线上生效需重建 API 服务。
