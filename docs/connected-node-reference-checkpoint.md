## 现场原因与修复

### 图片节点 7

失败请求实际属于上游文字节点：`POST /chat/completions#1`、模型 `gpt-image-2`、类型 TEXT、发送终态 failed。上游返回 HTTP 400，不支持 Chat Completions；该 Run 没有图片请求记录。具体项目与任务身份只保留在忽略的本地取证文件。

原画布保留「文字 → 生成图片 → 图片节点 7」整条生成链，图片回显只来自前端 Run 投影，持久化节点没有结果资产身份。普通拖线因此重新执行祖先。随后队列重投又把原错覆盖成“原请求可能已经送达，禁止重复创建”。

- 提交图片/视频目标时，只从同项目、同来源节点的成功归档记录中冻结直接连线图片的资产和版本；本次执行投影为 source，截断其祖先，不写保存画布。
- 显式图生图来源保持原资产/版本，手动输出优先；没有成功回显的节点保留旧 DAG，明确运行来源节点本身仍执行原配置。
- 归档、无权访问、版本缺失等情况在入队前明确失败，不退回生成上游。
- 明确拒绝的创建请求保留脱敏原错并停止队列自动重试。同 Run 人工重投、Worker/Prisma 重启后也不再次 POST；持久主键用于区分根任务与上游本地身份。
- 已有回执、归档或平台任务仍优先恢复；送达不明继续禁止重复创建。没有放松发送保护，也没有自动修改文字节点的模型。

### 连线别名“良”

旧实现只写资源卡片的 `resourceRefs`，正文仍是纯 text 块；现场旧引用还缺少 `assetVersion`。这不是来源图片节点标题未改的问题。

- 改名原子同步卡片别名和结构化正文，按资产、版本、权威旧别名定位；不覆盖其它提及、历史版本或同资产自定义名。
- 旧别名使用来源确知版本做只读投影，打开不保存。明确编辑才持久化；直接提交采用规范化文档，不需再次改名。
- 主动解绑或替换成纯文本后不会在刷新时重新绑定；版本未知或同名身份有歧义时明确提示，不借资源目录最新版猜测。
- 部署后只读打开真实视频节点，确认 11 处“良”均显示为结构化提及，原项目版本与内容摘要未改变。

### 悬浮操作与四侧连接点

实际节点工具栏改用无描边按钮，操作项增加 `6px 8px` 留白、背景反馈与简述 tooltip；菜单项同步处理，子菜单和 tooltip 不被滚动容器裁切。拖动、键盘焦点、禁用状态和节点尺寸保持原合同。

四侧位置固定，职责随节点类型、视频模式及模型规则变化：右侧输出，上侧通常接提示词，左侧接内容/首帧/自动识别的参考素材，下侧通常接负面提示词、首尾帧模式下接尾帧。资源节点只有右侧输出可连；未启用端口提供原因说明。不按邻居几何位置自动交换输入输出方向。
