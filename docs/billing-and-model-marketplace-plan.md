- 上游 `ModelCatalog` 仍按凭据保存候选目录；独立 `PlatformModel`、`ModelBinding`、`PricingVersion` 保存人工模型、版本绑定与售价。手动新建、候选导入及发布校验已实现：[`apps/api/src/model-marketplace.ts`](../apps/api/src/model-marketplace.ts)。
- 付费入口共用服务端报价和冻结模型快照，缺少有效平台价格或已确认报价时拒绝创建新收费任务。历史 `estimatedCost`、`Run.cost` 不参与用户扣款：[`apps/api/src/billing-submission.ts`](../apps/api/src/billing-submission.ts)、[`packages/billing/src/index.ts`](../packages/billing/src/index.ts)。

- 连接软禁用、目录刷新或更换 API 均不删除平台模型和历史价格；旧引用仅在精确上游 ID、连接及媒体类型能够唯一匹配时兼容解析，歧义要求重新选择。
- Sub2 视频真实验收返回了任务状态、视频内容和时长，但没有 usage 或费用字段：[`docs/live-provider-acceptance.md`](live-provider-acceptance.md)。

- 管理员、普通用户和配置权限的现有入口见 [`docs/admin-operations.md`](admin-operations.md)；账户基线见 [`TODO-ADMIN.md`](../TODO-ADMIN.md)。

## 目标与边界

系统尚未对客户开放，目标统一为平台服务端余额计费，不长期维护“上游计费 / 平台钱包”两套可选模式。“本地”指平台后端及数据库负责报价、余额和账单；Provider 继续提供模型能力，并向平台收取上游费用。

管理员维护独立的平台模型和 API 调用绑定。手工模型使用版本化平台售价；New API 联动模型直接沿用上游价格，无需重复定价。用户预付余额，提交前冻结允许消费的最高额度，再按实际执行的收费项结算。用户消费和 Provider 成本分别记账，所有付费入口共用现有 API / Worker / PostgreSQL 内的一个账务模块。

第一阶段结算币种已确认为人民币 `CNY`，由管理员发放内部测试额度并记录流水，个人账户尚无自充值入口；余额不足时联系管理员补充测试额度。最小单位为 `10^-9 CNY`（nanos），数据库使用 `Decimal(38,0)`，业务运算使用 `BigInt`，JSON 金额使用十进制字符串。暂不接支付宝、微信、Stripe 等真实支付，不实施多币种钱包。New API 联动按站点配置把额度换算为人民币，换算比例冻结在每次报价中；不调用外汇交易或行情服务。普通生成、批量生成、工作流、提示词优化、图片反推和显式重试均接入统一报价；原自动反推设置现在只提示用户到反推面板选择模型并确认费用，不再自动发起付费请求。

现有项目、资产、任务、凭据和 usage 记录继续保留，历史运行不追扣。数据库迁移已在隔离设施验证，现有应用数据库未改动。真实环境升级前必须备份并验证恢复；生产操作、破坏性迁移和真实付费验收仍需另行授权。

## 页面入口

PC Web 优先，入口与目录共用一份平台模型数据：

| 位置               | 页面或入口                    | 用途                                                                |
| ------------------ | ----------------------------- | ------------------------------------------------------------------- |
| 主导航“工作台”旁   | `/models` 模型广场            | 按文本、图片、视频、音频分类，支持搜索、规格、能力和价格详情        |
| 管理后台           | `/admin/models` 模型管理      | 同步导入、手动新建、编辑、API 绑定、定价、审核和上下架              |
| 管理后台           | `/admin/billing` 账务管理     | 内部额度调整、收费与成本依据、待核实处理及收费项退款                |
| 现有设置           | `/settings` 的“连接与 Key”    | 管理员维护 API 地址、Key 和上游目录刷新，保留节点默认等已有设置分类 |
| 节点编辑器         | 模型选择器                    | 读取同一份已发布平台目录，显示规格价格，不必先离开画布访问广场      |
| 头像菜单与个人中心 | `/account/billing` 余额与账单 | 查看可用余额、冻结余额、消费明细和退款                              |

管理员“模型管理”提供“同步全部连接到画布”“同步导入”和“手动新建”入口。普通用户可以看到全部已发布模型的展示信息、能力、售价、可用状态及脱敏连接来源（主机与 Key 安全尾号）。完整 API Key、内部凭据编号、指纹、上游成本明细与地址路径不进入普通用户响应。页面隐藏入口不能替代服务端权限校验。

保存或刷新连接后自动同步该 Key 的 New API 托管目录；已有连接可在设置或模型后台一次性全部同步。不同 Key 的同名模型保留独立平台身份，画布、提示词优化及反推均可选择。节点保存平台模型 ID，报价和生成冻结对应绑定，不随全局活动 Key 切换。菜单按连接分组，选中后持续展示尾号。同步逐连接报告上架数量及受阻原因，失败不删除已保存连接或历史模型。

“模型管理”和“同步导入”均可前往连接管理。“节点默认”的凭据来源通过下拉框选择继承、已保存连接或新增独立连接；选项显示地址、Key 尾号和当前全局状态。“连接与 Key”逐条提供删除按钮，非活动连接无需先激活。确认框说明同地址、同 Key 的版本及独立副本会一起移除，匹配当前全局连接时清空活动配置。删除后相关默认引用显示失效并需重新选择，模型、绑定和价格历史仍保留；新请求不能使用已删除连接，已受理任务按冻结凭据版本读取。该操作不撤销上游 Key，也不保证上游自行撤销 Key 后任务仍可执行。

## 产品角色和主流程

### 管理员

1. 在“设置 → 连接与 Key”中维护 Sub2/New API 等连接。
2. 保存连接后自动同步可用 New API 模型；已有连接使用“同步全部连接到画布”，也可选择候选导入或手动新建。
3. 配置展示信息、媒体类型、规格，以及连接、真实上游模型 ID 和调用合同的绑定。
4. New API 联动中勾选合同完整的模型即可建立绑定、沿用价格并上架；手工模型则配置单位、售价和版本后上架。
5. 发放测试额度，处理待核实事项和收费项退款；核实 Provider 原币种成本并保存依据。

### 普通用户

1. 在主导航进入“模型广场”，或直接在节点按连接来源选择已上架模型与规格，同名模型用 Key 尾号区分。
2. 查看本次任务的报价、最高扣费额度和余额；优化和反推也分别先确认费用。
3. 确认后由服务端确定付款账户、冻结余额并使用对应 API 连接执行。
4. 在个人账单查看收费明细、冻结、释放或退款状态，通过任务关联查看结果。

### 任务收费流程

```text
选择平台模型与规格
  → 服务端验证有效调用绑定、价格版本及费用上限
  → 原子保存任务、报价快照、余额冻结和待投递记录
  → 投递队列，按实际子调用保存发送意图和 request_id/task_id
  → 成功且结果可交付：按确认用量或已发布固定价逐项结算，释放多余冻结
  → 明确未执行或失败的收费项：释放对应冻结
  → 请求结果或计费用量未知：待核实，不自动重发
  → 仅上游成本未知：用户账单正常结算，Provider 成本单独对账
```

一个 Run 可以有多条真实子调用收费明细，Run 账单只是汇总。每个收费项使用稳定业务身份；浏览器重复提交、Webhook 重放、队列重投及 Worker 恢复只能命中原记录，不能再次冻结或扣款。用户明确发起新的付费重试时才创建新执行身份和新报价，恢复已有结果不算新消费。

数据库 UUID、普通外部 `run_*` 和幂等外部 `run_idem_*` 必须解析到同一原始运行身份；查账、查询、列表、取消和重试不能因 ID 形式不同绕开原冻结记录，缺失映射时拒绝操作。待核实调用可请求不冻结、不执行的只读报价，但实际重试确认仍返回 409；运行历史被删除后，原账单可继续通过外部运行编号查询。

## 模型广场

### 平台模型、调用绑定和 API 连接

管理员可在模型列表或详情点击删除并确认。删除使用 `deleted` 状态保留商品身份，退出后台列表、广场及新任务选择；未消费的旧报价也不可再提交。已受理任务继续使用冻结快照，绑定、价格版本和历史账单保留。托管同步遇到已删除的同身份模型明确拒绝恢复；如需重新配置，可以手动新建独立商品。暂停仍适用于以后打算重新上架的模型。

连接选择统一显示地址和遮罩尾号，如 `…abcdefgh`。正常 Key 显示末尾 8 位；长度不超过 8 时最多显示末尾半长且不超过 4 位，单字符或不可解密时显示“尾号不可用”。旧密文可直接读取尾号，无需重新添加 Key；内部指纹仍用于身份匹配，不在界面显示，也不把尾号作为唯一身份。

| 对象     | 保存内容                                                                               | 变化边界                                                       |
| -------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 平台模型 | 稳定 `platformModelId`、展示名称、介绍、分类、规格、发布状态                           | 由管理员维护，价格版本关联此身份；更换连接不改变模型身份       |
| 调用绑定 | 平台模型、连接身份、精确 `upstreamModelId`、接口合同、已验证能力与参数限制、绑定修订号 | 验证后显式启用，变更只影响新任务；首期每个模型启用一个绑定     |
| API 连接 | 地址、加密 Key、凭据版本、可用状态                                                     | 管理连接及轮换；保留历史任务所需版本，不级联删除平台模型或价格 |

现有 `ModelCatalog` 继续作为连接范围的上游候选目录缓存。平台模型与人工设置独立持久化，不把平台售价或商品身份寄存在刷新时会替换的目录行中。节点和项目默认模型引用平台模型身份；提交时由服务端解析并冻结绑定、真实上游模型 ID、凭据版本、合同和价格版本。

同名不代表同一个模型，不能按展示名称自动合并或替换绑定。管理员可以修改展示名称，但发送给 Provider 的 `model` 必须保留已确认的精确 ID、大小写和后缀。

### 同步导入

同步请求使用管理员指定连接的目录接口。现有广场、通用 `/v1/models` 和公开 `/api/pricing` 仍支持草稿导入；“New API 模型与价格联动”使用鉴权目录，勾选合同完整的模型后建立绑定与价格策略并上架。刷新目录本身不自动导入全部模型。

| 上游数据                 | 保存与使用规则                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| 模型 ID、名称            | ID 必须存在；缺少名称时显示 ID。它们用于选择及绑定上游模型，不自动覆盖人工展示名               |
| 媒体类型、能力、参数限制 | 仅把明确返回的字段作为来源证据；缺失标记待确认。上架前按实际合同验证，不依据名称推断就承诺能力 |
| `price` / `pricing`      | 保存为 `provider_declared` 成本参考，记录单位和来源，不自动成为用户售价                        |
| 目录时间与来源快照       | 保存连接身份、同步时间和脱敏后的响应；不保存 Key、认证头或敏感签名 URL                         |

后续同步只更新上游来源数据及变更提示，保留人工名称、介绍、能力修正、平台价格和发布状态。已发布能力与上游新证据冲突时标记待复核并暂停不兼容的新调用，不能静默扩展能力。单次刷新失败保留上次目录并显示过期状态；成功刷新后缺失的条目标记待核实，不自动删除平台模型、手工模型或调用历史。

`/v1/models` 不保证返回完整能力或费用，也不保证覆盖可通过精确 ID 调用的全部模型。目录是否出现与实际可调用性分别验证；确认绑定失效时，模型保留并显示暂不可用。

#### New API 价格沿用

用户已确认保留画布人民币钱包，并直接沿用 New API 的价格。New API 保存生效价格；Canvas 可以编辑其原配置，保存为草稿，在下次明确点击“同步模型与价格”时写回 New API，重读一致后显示新价。手工模型仍可独立定价，New API 托管模型不再逐项填写人民币单价。

模型管理首屏提供广场 URL 输入，已确认来源为 `https://api.lolicon.beer/pricing`。输入站点或广场地址即可读取所有公开模型、分组、阶梯、任务规格与插件价格；换域名后修改此地址即可。原显示算法复制自 `D:/newapi/web/src/features/pricing @ 8b6534ba9`，保留版权与许可，币种跟随上游状态。普通用户广场优先展示该目录，原画布连接与手工模型保留。

浏览目录无需管理授权；改价需独立的 New API 超管个人访问令牌（PAT），服务端加密保存，仅通过既有 `/api/option/model_pricing` 读写原配置，不加入用户可选的调用 Key。草稿与上游版本、来源修订绑定，价格冲突、无权限、响应不明均保留草稿，不覆盖其他管理员的新价格。换站清除旧授权、保留旧站草稿，不能把旧授权发给新域名。调用 Key 及其地址仍在“连接与 Key”中管理，不因广场同名模型自动改绑。详见[价格同步检查点](newapi-pricing-sync-checkpoint.md)。

两边新增受实际调用 Key 约束的目录、预估和最终结算回执。New API 负责解析分组、表达式及插件费用；Canvas 负责人民币预算授权、冻结、交付及结算。换算采用 New API 站点的 `USDExchangeRate` 和配额单位，冻结在报价中，不使用访客最低倍率或充值促销折扣。后续新报价读取最新配置，历史账单保留原依据。

预估只用于本次人民币预算，不承诺上游费用上限。用户实际扣款为最终费用按冻结换算后的金额与已确认上限中的较小值，超出部分由平台承担并可对账。没有最终回执时保持待核实，不按预估金额冒充实价。恢复仅查询原请求或任务，不重发生成请求。

同步时仅对具有明确调用合同的模型自动建立托管绑定和价格策略；缺少合同的模型列出具体原因。已有人工验证的绑定可切换为跟随价格。更换连接不删除平台模型和历史记录，重复同步不覆盖人工名称、介绍或手工定价模型。

保存连接后自动联动全部合同完整的模型；“模型管理”和“连接与 Key”提供“同步全部连接到画布”。仍可使用“同步导入 → New API 模型与价格联动”选择导入。批量同步每条连接仅读取一次鉴权目录，沿用 New API 价格；缺桥接、合同或能力明确提示，不能回退到匿名参考价。手工模型的“价格来源”也可选择“沿用 New API 价格”，不显示人民币单价输入框。人工价格、暂停和删除状态保持不变；已人工改绑的商品不会被旧来源同步改回。接口与本轮验证见[多连接检查点](canvas-connections-checkpoint.md)。

联动接口均使用原调用 Key，返回直接 JSON：`GET /v1/canvas/catalog`、`POST /v1/canvas/estimate`、`GET /v1/canvas/receipts/:requestId`。估算使用真实计费引擎及当前 Key 可用路由中的最高预扣估算，不发生成请求。创建请求身份只取 `X-Oneapi-Request-Id`，轮询编号独立保存。报价有效期取上游有效期与本地五分钟中的较早值；组、价格在执行时仍可能变化。管理员账务详情可查回执和冻结换算依据。

自动导入只接受管理员显式声明的标准端点，或真实注册的 `openai_video` 插件协议；不根据模型名字猜能力。仅支持 Responses 或缺少协议资料的模型暂不可直接联动。当前自动目录只声明文本输入，图片提及等额外能力仍需实际验证。工作流输入尚未确定且上游插件不能估算时，报价明确失败，不填造输入或改为免费。

部署需要同时升级 Canvas API/Worker 与 New API，并在 New API 设置 `CANVAS_BRIDGE_ENABLED=true`；默认关闭。New API 启动新增 `canvas_receipts` 表，无旧余额迁移。开启桥接后用户及令牌相关额度变更同步落库，不能以批量队列接收成功作为最终账单；因此高负载生产环境还需验证数据库写入容量。升级前备份数据库、资产与密钥。关闭入口可停止新联动；已有冻结、在途任务和回执必须由兼容版本处理，不能直接降级或删除回执表。

最终账单待核实、表达式结算失败、计费单位中途变化、资金与令牌部分写入或进程中断时，不伪造终态。自动恢复只重查原回执；已归档任务不会再次生成。无法确认的账务保留人工核对事项。取消或归档失败时仍可独立读取最终上游成本，用户收费遵守交付条件。

- 管理员在“同步导入”选择“New API 定价目录”和已保存连接。服务端从连接地址派生固定目录路径，保留部署前缀，移除尾部 `/v1`；不接受任意请求地址，不转发 API Key、用户会话或 Cookie，不跟随重定向。

### 手动新建和手动定价

管理员无需先成功同步目录，即可手动新建平台模型：

1. 填写展示名称、介绍、分类、媒体类型、规格和排序，先保存为草稿。
2. 选择 API 连接，填写真实上游模型 ID、接口合同、能力及参数限制；记录依据和验证状态。
3. 配置计费单位、各规格单价和价格版本；未定价不等于免费。
4. 检查绑定、能力、计量来源、报价上限与售价后上架。需要真实生成验证时另按真实 Provider 验收规则执行。

手工创建的数据不会被上游刷新覆盖。模型 ID 可以尚未出现在目录中，但必须有可验证的调用合同，不能通过填写任意名称就宣称支持生成。展示名可自定义，能力和参数仍受实际 Provider 限制。

### 更换 API 后保留模型

| 操作                        | 平台模型与价格                   | 调用行为                                               |
| --------------------------- | -------------------------------- | ------------------------------------------------------ |
| 轮换同一连接的 Key          | 保留模型身份、人工字段和价格     | 验证新凭据权限后用于新任务，历史任务保留原版本         |
| 换到另一家 API              | 保留模型、规格、售价和画布引用   | 核对实际模型及合同，创建并启用新绑定；不因同名自动转接 |
| 新 API 不支持对应模型或规格 | 保留记录                         | 标记暂不可用或禁用不支持的规格，禁止提交对应新任务     |
| 停用或移除旧连接            | 保留平台模型、旧绑定、价格和账单 | 无有效绑定时禁止新调用；不级联删除平台数据             |
| 上游目录刷新失败或模型缺失  | 保留人工记录和已有价格           | 标记过期或待核实，确认失效后阻止新调用                 |

例如平台模型绑定 API A 后改用 API B，只替换经验证的调用绑定，平台模型编号与售价可以保持不变；真实上游模型、协议或规格不兼容时不能仅改地址继续发送。

已提交任务固定原连接、凭据版本、模型 ID、合同、参数和价格。停用旧 API 前先处理在途任务；旧凭据在供应商侧失效时记录恢复受阻，不能拿新 API 查询旧任务 ID，也不能自动换 API 重新发起付费创建请求。

### 模型状态

发布状态由管理员维护：

- `draft`：手动新建或从候选目录导入，未审核，普通用户不可见。
- `published`：已审核上架；实际选择和提交还需有效价格与可用绑定。
- `paused`：暂时下架，历史任务仍可查询。

可用状态单独记录：绑定经确认不可用时显示 `unavailable`，保留人工发布状态和历史记录；恢复可用需重新验证。同步失败仅标记来源过期，不能直接视为 Provider 已下架。

### 价格规则

手工平台价格由管理员配置为不可变版本，关联平台模型及规格，包含结算币种、精度、舍入规则、生效时间、计量来源和收费单位。New API 联动价格版本保存 `upstream_cost/newapi_receipt` 策略，实际预估和结算依据保存在每次报价及收费项。两种方式均不能覆盖旧任务和历史账单。

| 类型 | 首期收费方式                           | 定价和计量边界                                                                        |
| ---- | -------------------------------------- | ------------------------------------------------------------------------------------- |
| 文本 | 固定按次；Token 规则保留但暂不开放报价 | 输入、输出 Token 单价按百万 Token 保存；缺少可信输入计量时返回 `metering_unavailable` |
| 图片 | 按成功交付的图片张数                   | 根据模型、尺寸、质量分别定价，数量计入报价和明细                                      |
| 视频 | 按次或按秒                             | 每个价格版本明确选择规则；按模型、分辨率、时长和数量报价，明确计费时长来源与取整方式  |
| 音频 | 按字符数或时长                         | 按模型合同确定字符统计、输入或输出时长及单位，不能混用                                |

缺少可靠用量的模型可以预先发布固定单次价格；固定价覆盖哪些产物必须写清。已经按用量报价的任务若最终缺少计量数据，进入待核实，不能临时改用固定价或以估算用量扣款。

当前执行边界由 [`billing-submission.ts`](../apps/api/src/billing-submission.ts) 和 [`billing-execution.ts`](../apps/worker/src/billing-execution.ts) 校验：

- 每个真实子调用只交付一个结果，`n` 只能省略或为 `1`；批量通过多个独立调用产生明细，不能给一次调用设置 `n > 1`。
- 按秒报价需要明确、一致的正整数 `duration` / `seconds` / `durationSeconds`，不能用自动时长或估计值冻结。`output_metadata` 仅在归档资源元数据状态为 `ready` 且有合法时长时结算；`provider_usage` 尚无已接通的可信秒数合同，实际交付后仍进入待核实。
- 按字符仅支持 `openai-audio` 的完整冻结输入，以实际发送文本的 Unicode 码点计数，范围为 1–4096。连线或提及导致输入要到 Worker 才能确定时拒绝此种报价。
- 按秒规则保存 `exact` 或 `ceil_second` 的时长取整方式；金额在整个收费项计算后才向上取整至 nanos，不逐次舍入到分。

手工模型的 Provider 参考价只用于管理员定价，更换 API、刷新目录和上游涨价不自动改变其售价。New API 联动模型的新报价会读取最新上游价格，原报价的人民币换算和用户预算保持冻结。缺价格时禁止平台付费提交；免费也须有明确零价配置。

提交前冻结模型、绑定修订、参数、价格版本、报价有效期和最高扣费额度。文本按可验证输入量及最大输出额度报价；无法给出可执行上限的规则不得开放预付调用。报价过期或参数变化需重新报价，已受理任务继续按快照执行，最终用户扣费不得超过确认上限。工作流报价覆盖计划中的所有收费子调用，未执行部分释放，新增付费范围需重新确认。

## Provider 成本与用户收费

系统分别保存提交前报价及上限、用户实际消费 `user_charge`、上游实际成本 `provider_cost`。`Run.cost` 的历史估算不能作为实际用户扣款或真实 Provider 成本。普通用户查看自己的报价、消费、冻结和退款；管理员在“账务管理 → 收费与成本”按任务查询收费项，点击“查看依据”读取用户人民币结算、供应商原币种事实、独立人工裁决、历次审计及交付计量依据。待核实列表也提供同一只读详情；查询不会换汇、补扣或重发调用。

用户结算与上游成本使用独立状态。手工模型的结果可交付、固定价或真实计量已确认时，即使 Provider 没有返回费用，用户账单仍可按已发布规则结算，成本标为 `unknown` 或 `pending_reconciliation`。New API 联动模型以原请求最终回执作为扣费依据，回执缺失时保留冻结和待核实事项，不能按预估扣款或伪记免费；超期处置仍需运营核对。

首期按成功交付收费：明确失败、未执行或最终无法交付的收费项释放冻结，若上游已产生费用仍记录为平台成本。局部成功的工作流结算已交付项并释放其他确定未收费项；已发出的请求不会因本地点击取消就自动认定失败或免费。

### Sub2/New API 处理规则

- 普通 `/v1/models` 响应用于同步模型目录，不保证提供完整计费规则。
- 普通生成响应不应假设包含 `actual_cost` 或 `total_cost`；Token 数、媒体时长等计量信息和明确金额分别保存。
- 视频报价使用固定的模型、分辨率、时长规则、数量和价格版本；结果中的媒体时长只有符合该价格版本的计量合同，才能作为结算用量。
- 本地规则计算的是平台售价或成本估算，不等于 Provider 已确认的实际扣款；不同币种成本保留原币种，首期不自动换汇计算利润。
- 保存 `request_id`/`task_id` 后，按具体部署已确认的管理 usage 接口和权限对账。不能把公开文档或普通聚合 usage 当作当前部署已支持逐任务查询的证明。
- Provider 返回明确金额和币种时，保存脱敏 usage、来源和解析时间；重复事件不能覆盖首条事实，冲突进入对账，修正保留关联记录。

原币种成本使用 `Decimal(38,12)`，最多十二位小数；供应商直接返回的金额先规范化科学计数法，超出范围或精度明确拒绝。New API quota 使用整数分数换算 USD，统一向上取整至十二位小数，原始 quota 与单位保留在回执中。管理员 `confirm_cost` 裁决保存操作者、原因、金额和币种证据，已存在的首条成本金额及来源保持不变。待核实事项关闭后出现新的冲突会重新打开并追加旧决策审计；已裁决事实的重复通知不会反复重开。成本裁决和执行项释放均与事项关闭在同一事务提交，并发只能成功一次。

Provider 响应先保存脱敏 `received` 收据及明确费用，正常路径随后归档、结算用户费用、记录 Provider 成本；若收到响应后取消或归档失败，恢复仅补记原成本，不把响应本身视为已交付。旧 `UsageLedger` 为 `Decimal(18,6)`，不能表示的小额或大额成本仍精确保存在 `ProviderCost`，并记录 `usageStatus=legacy_unrepresentable` 及原因；不向旧账本写零或舍入金额，不因旧账本限制阻断已确认交付。

钱包金额固定采用 `Decimal(38,0)` nanos，最大值为 `10^38 - 1`；不得使用 JavaScript 浮点数作为用户账务来源。`UsageLedger` 继续保存上游金额事实，不直接承担用户余额或冻结状态；不覆写历史流水，退款和纠错以关联的反向或调整流水表达。

### 结算状态

报价保存在 `BillingQuote`，确认受理后才生成 `ChargeItem`。每条收费项的用户结算状态为：

- `HELD`：已冻结用户余额；
- `SETTLED`：结果可交付且已按确定规则结算；
- `RELEASED`：确定无需用户付费，已释放对应冻结；
- `PENDING_VERIFICATION`：执行结果或计费必需用量未知，保持冻结等待核实，不因超时或本地取消自动结算、释放；
- `REFUNDED`：已结算项完成全额退款；部分退款以独立金额与流水记录。

Provider 成本另用 `unknown`、`pending_reconciliation`、`confirmed`、`disputed`、`adjudicated` 状态；最后一项表示管理员裁决已记录但原始金额保留。它们不作为用户账单状态。Run 账单返回逐项状态，允许部分结算、部分待核实，不用一个“任务失败”覆盖所有子项。

### 事务、幂等与恢复

- 冻结、结算、释放和退款在数据库事务内锁定钱包行或使用等价并发控制，保证可用和冻结金额均不为负。结算扣除实际消费并释放该项多余冻结，累计退款不得超过已结算金额，累计消费不得超过确认上限。
- 服务端从认证身份确定付款人；普通用户不能在请求中指定他人钱包、价格或绕过收费。内部测试额度也通过流水发放。
- 以持久化的 Run、节点、逻辑子调用身份建立收费项唯一约束，每个财务动作另有唯一 `idempotencyKey`。队列尝试次数、Worker 重启和回调 event ID 不得把同一调用变成新收费项。
- 任务、报价、冻结及待投递记录须原子写入；队列投递使用 outbox 或等价可恢复机制。投递失败可重投同一任务，不能再次冻结；未冻结成功不得发送 Provider POST。
- Provider 请求前持久化发送意图；已知任务 ID 优先查询或恢复归档。结果未知时不自动重发创建请求或切换 API，不把“本地取消”当作远程任务已经终止。
- 已归档结果的本地记账失败先恢复原 Run；当前队列最多执行三次自动尝试，耗尽后建立独立 `worker_recovery` 事项并保留交付证据，不能对已归档子项再次调用 Provider，也不能用人工释放或成本确认代替恢复。恢复原账务成功后关闭该事项。
- Redis 中原失败任务仍存在时，运维可在核对队列、Run 身份、冻结快照和持久取消状态后对同一 job 执行 `job.retry('failed')`。该操作恢复整个 DAG：已归档子项只补账，尚未发送且已授权的下游节点仍可首次执行；只有全部执行节点均已归档，或已有持久取消意图时，才能保证恢复过程零新增 Provider POST。已发布 outbox 对应的 Redis job 丢失后，尚无经过验收的安全重建入口，不能自行新建任务或清除原发送证据。
- 重复结算金额与原消费不一致时，保留原流水并建立 `settlement_conflict`。后台只读展示冲突依据，管理员先核对原流水及交付计量，确认差错后另行退款；`confirm_cost` 与 `release` 均不能关闭此类事项，完整纠错及关闭流程仍需运营验收。
- 待核实事项保存 24 小时截止时间，后台按截止时间排序并显示逾期。到期不自动退款、补扣或重发；外部查询合同和运营告警仍待接入。管理员核实释放时，收费项、释放流水、事项关闭及操作者审计同事务提交；释放或退款后收到迟到结果不自动重新冻结或补扣用户。
- 人工释放在事务内检查已归档证据和开放 `worker_recovery`；即使另有 `execution` 事项，也不能释放应恢复账务的已交付收费项。

### 运维恢复边界

当前没有面向运维的恢复 API 或 CLI，以下为已在隔离集成测试演示的同 job 修复条件，不是可直接批量执行的恢复工具：

1. 确认外部 Run 编号、`RunOutbox.queueName` 和 Redis namespace，核对 Quote、RunCharge、归档资产版本和 ProviderJob 指纹指向同一冻结执行；先修复原数据库、存储或账务故障，不修改执行身份、释放冻结或替换 payload。
2. 原 Redis job 必须仍存在，状态为 `failed`、`attempts=3`、`attemptsMade>=3`，且没有执行中的同一任务，才可对该 job 调用 `job.retry('failed')`。不要调用 HTTP 付费重试，不执行 `resetAttemptsMade`；保留已消耗次数，默认不会重新获得三次自动尝试。
3. 恢复会遍历整个 DAG。若本次运维只允许补账且要求零新增 Provider POST，应先确认全部执行节点均已有归档证据，或已有持久取消意图；否则未发送的原授权下游节点可能首次执行。
4. 完成后核对仍是同一 Run、原资产可读、每项仅一次结算、Provider POST 数符合预期且 `worker_recovery` 已关闭；缺少计量的 `execution` 事项仍可能保持开放，不能据此再发起生成。

数据库长期不可写时连 `worker_recovery` 事项也可能无法建立，值守仍需查看 failed jobs 和 Worker 错误日志。已发布 outbox 对应 Redis job 丢失时，安全重建入口尚未实现及验收；不得把 `publishedAt` 改为 `null` 或自行 `queue.add` 冒充已验证恢复。故障发现、告警、运行手册工具化和结算冲突事项关闭仍保留为运维待办。

## API 与页面执行清单

### 管理员 API

以下接口已实现并登记 OpenAPI，均使用真实管理员会话；服务 Token 和客户端自报角色没有钱包或模型管理权限：

- `POST /v1/admin/model-marketplace/sync`：刷新指定连接的候选目录，`sourceType` 为 `models`（缺省）或 `newapi_pricing`，返回候选、缺失列表和同步结果，不修改平台模型售价；
- `GET/POST /v1/admin/model-marketplace/models`、`GET /v1/admin/model-marketplace/models/:id`：查询模型及详情、从候选目录选中导入或手动新建草稿；
- `PATCH /v1/admin/model-marketplace/models/:id`：修改展示信息、规格、排序及人工发布状态；
- `GET/POST /v1/admin/model-marketplace/models/:id/bindings`：维护调用绑定版本和验证结果，显式启用兼容绑定；验证动作默认只做配置检查，真实生成单独授权；
- `GET/POST /v1/admin/pricing-versions`：创建和查看价格版本；
- `GET /v1/admin/wallets/:userId`、`POST /v1/admin/wallets/:userId/adjust`：查看余额和人工额度调整，要求原因、幂等键和审计；
- `GET /v1/admin/charge-items`：分页查询收费项及原币种成本摘要，支持按 `runId` 精确筛选，每页 50 条；
- `GET /v1/admin/charge-items/:id`：使用一致读事务查询收费、交付计量、成本事实、独立裁决和全部状态的核实事项；历次账务审计按 `historyPage` 每页 50 条返回；
- `GET /v1/admin/model-marketplace/sync`：按连接及 `sourceType` 查询同来源最近同步结果及保留候选；
- `GET /v1/admin/reconciliation`、`POST /v1/admin/reconciliation/:id/resolve`：查询待核实事项，原子确认原币种成本或释放执行冻结；`worker_recovery` 需恢复原 Run，`settlement_conflict` 需核对原消费并另行退款，两者不能通过这两个裁决动作关闭；
- `POST /v1/admin/charge-items/:id/refund`：按收费项追加退款流水，累计退款不超过原消费，记录操作者、依据和幂等键。

### 普通用户 API

- `GET /v1/model-marketplace`：只返回已发布平台模型、能力、规格、平台价格和可用状态；
- `GET /v1/account/wallet`：余额、冻结余额和币种；
- `GET /v1/account/billing`：个人账单和任务关联信息；
- `POST /v1/billing/quotes`：按实际执行计划计算报价及最高额度，返回有有效期且绑定付款人、模型与参数的报价标识；
- `GET /v1/runs/:id/charge`：查看本人任务报价、子调用收费明细、冻结、结算及退款状态。

`POST /v1/billing/quotes` 接受 `{ path, body }`，仅包装普通生成、反推、优化和重试的已允许路径，复用原入口的权限与参数校验；它不是任意 URL 代理。也可以向原提交路径发送 `quoteOnly: true` 获得报价，再用完全相同的输入和 `quoteId` 确认。有效期为五分钟。已受理的同一优化或反推返回已有任务，不再确认和生成第二笔消费。

所有付费运行入口必须携带用户已接受的有效 `quoteId` 或等价服务端报价身份，服务端校验付款人、执行计划、模型绑定、参数及已确认最高额度后才冻结和投递。客户端自报金额无效；报价失效或需要重算时返回新报价等待用户确认，不得现场生成后直接扣款。既有 `/v1/models` 和旧节点引用需要明确迁移适配，不允许通过旧路由、原始 `modelAlias` 或 `credentialId` 绕过平台模型发布、价格和付款权限检查。

普通用户响应不返回 Provider Key、凭据 ID、内部成本明细或管理接口地址。管理员成本详情对交付、计量、成本证据和审计摘要使用嵌套字段白名单，只展示核账所需身份、金额及依据；不返回凭据、用户输入、生成正文或完整绑定快照。

## 验收标准

### 功能验收

- 同步导入和手动新建均可完成草稿、绑定、定价、上架；同步失败、目录缺失和再次刷新不删除人工记录、不覆盖人工名称及售价。
- 更换或停用 API 后平台模型、画布引用、规格和价格保留；无有效绑定时新任务被阻止。同名模型不被自动合并，旧任务按原合同恢复。
- 主导航广场、管理员模型管理和节点选择器使用一致目录；权限在 API 生效，普通用户不能读取 Key、内部成本或他人账单。
- 余额不足、模型未发布、缺价格、绑定失效或报价超期时，付费 POST 次数为零；参数变化不能复用旧低价报价。
- 并发提交不超额冻结；重复提交、回调重放、队列重投和 Worker 重启不重复冻结、扣款、释放或退款。
- 多节点、批量、优化和反推逐真实子调用形成明细，部分成功、失败、取消、超时及归档恢复分别正确处理，不只按 Run 总状态结算。
- 已交付且计量明确时，上游费用缺失只使成本待对账；缺少用户计量时不按估算扣款。结果未知不自动重发或直接按零处理。
- 失效报价须重新确认后才冻结；已释放或退款项收到迟到结果不会自动补扣，处理依据与上游成本可追溯。
- 价格与绑定版本变更不影响历史账单和已受理任务，用户最终消费不超过确认上限，历史运行不追扣。

- 迁移前记录目标环境、提交/镜像、数据库与队列，停止旧版本接受新任务，备份数据库、对象存储、配置及必要密钥，并在独立恢复目标确认备份可读。生产备份恢复尚未演练，不能把隔离迁移通过作为替代。
- 本次迁移依次为 `20260919090000_platform_billing`、`20260919093000_platform_model_defaults`、`20260919100000_billing_outbox_queue`，新增账务和模型表、默认模型可空平台身份及 outbox 队列名。它们不删除历史项目、资产、usage 或凭据；首次迁移写入 `BillingActivation`，不得人为回调该时间制造历史豁免。
- 在已确认的目标连接注入 `DATABASE_URL` 后，依次运行 `pnpm db:validate`、`pnpm db:generate`、`pnpm exec prisma migrate deploy`、`pnpm exec prisma migrate status` 和对应 schema diff；生产使用已提交的迁移，不运行 `migrate reset` 或 `db push --accept-data-loss`。任一步失败保持暂停新受理并排查，不跳过失败迁移。
- API、Worker 和 Web 使用同一兼容版本部署。API 与 Worker 必须配置持久化数据库、同一 Redis/队列和可恢复资产存储；真实模型调用要求 `RUN_SERVICE=bullmq`，内存模式只允许明确 Mock。发布前补齐模型绑定、价格及账户额度；旧引用有歧义时由管理员确认映射，不按名称猜测归属。
- 旧 Run、usage 和资产保留为历史记录；不能从 `estimatedCost` / `Run.cost` 构造历史消费，也不能把已有上游账单当作用户充值。切换前提交的任务按冻结合同继续完成且不追扣，切换后统一进入平台账务流程。
- 按接口、字段与迁移影响更新 OpenAPI、客户端及文档，验证所有旧入口都不能绕过新账务；不以保留兼容接口为理由维护长期双计费模式。
- 回滚优先停止新付费任务受理，保留已冻结任务的查询、结算与退款能力。已有真实流水后不能用旧数据库快照覆盖，不能降级到不识别账务或绑定快照的旧 Worker；通过兼容版本及补偿流水恢复。
- Provider 合同变化只产生待复核来源或绑定版本，不自动更新售价。人民币精度及当前计量/舍入规则已固定，尚未确认的 Token、秒数 usage 合同和运营处置时限继续保留为开放前条件。
- 当前 Helunox/Sub2 等部署的逐任务费用字段、管理 usage 权限和查询合同仍需外部验收；真实成本只能来自明确费用或可核对账单，不能由倍率反推。
