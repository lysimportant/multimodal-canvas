# 模型调用恢复计划

更新时间：2026-09-20。优先级：P1。状态：计划已整理，功能实施和运行环境验收待执行。本轮只写文档、核对实现和运行只读检查，不部署、不改价、不删除数据、不发起付费生成。

## 1. 建议与完成目标

建议保留已确认的人民币钱包和 New API 原价，修复连接、能力同步及调用绑定，让用户恢复“选连接和模型、放入素材、确认费用、生成”的操作。不再要求管理员为同一批 New API 模型重复填写价格、输入能力或逐个手动上架。

“像以前一样正常调用”按具体模型和输入组合验收：现有连接中的已适配模型可以选择；过去支持的文字、首帧、首尾帧和参考素材能正确送到对应接口；任务可查询、归档并打开结果。保留所有已保存 Key 的选择入口和安全尾号，不随全局活动 Key 切换而改用其他连接。

本方案优先恢复当前受阻的 `MiniMax-H3`、`wan3.0-video`、`wan3.0-video-prime`，同时检查已有成功证据的文字、图片及其他视频调用。公开广场里仅有名称和价格、但尚无已确认调用协议的模型，不列为已经可调用。

此前讨论的“移除画布钱包和模型广场”是另一条产品路线，会同时改变费用确认、任务授权、历史节点引用和账务处理。它不是修复本次图片拦截的必要条件，本计划不执行该删除。若以后改为仅由 New API 扣费，应单独设计调用与账务解耦，不能直接删表或关闭 Worker 授权检查。

完成标准：当前三款视频模型各自已确认支持的输入组合通过下方验收；至少一个普通生成、一个旧节点、两个 Key 的模型选择、一个工作流和费用确认流程取得证据。没有真实上游验收的组合继续注明待验证。

## 3. 当前是否在发送前提示费用

**是。当前已经实现发送生成请求前的费用确认，显示的是根据估算得到的人民币预算上限，不是最终精确账单。**

现有顺序如下：

```text
点击生成
  → 校验模型、连接、输入素材与参数
  → 使用原 Key 向 New API 请求费用估算
  → 显示每项最高费用、合计最高费用、可用余额、报价有效期
  → 用户点击“确认并生成”
  → 原子创建任务并冻结本次授权额度
  → Worker 向 New API 发送生成请求
  → 结果交付后读取原请求的最终账单，结算并释放多余冻结
```

估算会访问 New API 的 `POST /v1/canvas/estimate`，但不调用生成接口，不预扣生成费用。Canvas 此时只保存报价，没有冻结钱包，也没有创建生成任务。当前 H3 图片能力校验先失败，因此用户还看不到后面的费用弹窗。

| 项目       | 当前实现                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| 弹窗内容   | 模型名称、计费方式、数量、每项最高人民币费用、合计、可用余额及到期时间                                        |
| 确认按钮   | `确认并生成 · 最高 ¥…`；取消、关闭页面或切换账户均不提交新生成                                                |
| 价格来源   | New API 托管模型通过原 Key、精确模型和输入参数预估，复用上游原价格规则；无需在画布另填价格                    |
| 报价有效期 | 本地五分钟与上游有效期取较早者；过期要重新报价并再次确认                                                      |
| 请求变化   | 已保存的报价绑定模型、连接版本、参数和冻结输入；不匹配则拒绝，不能拿旧报价执行新请求                          |
| 余额不足   | 确认按钮禁用；后端仍原子校验余额，避免并发超用                                                                |
| 估算失败   | 不创建运行、不冻结余额；明确显示原因，不把失败当成免费                                                        |
| 最终扣费   | 对于已交付的 New API 托管任务，以原请求最终净 quota 按报价时冻结的换算规则结算，Canvas 扣款不超过用户确认上限 |
| 回执未完成 | 保持待核实，继续查询原任务/回执；不把估算冒充实际费用，不重新发起生成                                         |

示例仅说明规则，不代表某个模型的实际价格：确认最高 ¥1.00，最终费用 ¥0.80，则结算 ¥0.80、释放 ¥0.20。若上游实际费用超过 ¥1.00，Canvas 钱包仍按 ¥1.00 封顶，差额由平台承担。这个上限约束 Canvas 钱包，不能保证 New API 本身不会扣除更高的上游费用；报价也不会锁住上游之后修改的价格或分组。

已有入口：[费用弹窗](../apps/web/src/marketplace/QuoteDialog.tsx)、[报价与确认请求](../apps/web/src/marketplace/quote-client.ts)、[API 报价](../apps/api/src/billing-submission.ts)、[结算规则](../packages/domain/src/billing.ts)、[Worker 最终回执](../apps/worker/src/billing-execution.ts)。本轮核对了当前源码、定向测试和 8080 已发布静态资源，未在当前会话完成实际报价弹窗或付费生成验收。

## 4. 分阶段执行

### 阶段 A：先让现有 H3 修复生效

责任范围：New API 宿主版本与插件状态、Canvas API/Worker/Web 镜像、当前连接目录同步。

1. 记录双方运行版本、镜像、Hailuo 实际生效版本、待处理任务和当前模型绑定；备份数据库、资产及密钥，保留旧镜像。
2. 在隔离环境重现当前图片拒绝，再使用已提交修复验证相同输入可以获得报价，且生成请求计数为零。
3. 获得运行环境更新授权后，配套部署两端修复。New API 必须包含宿主桥接改动；检查 Hailuo 1.1.4 或包含相同适配的后续版本实际生效，避免旧上传插件覆盖工厂版本。
4. 重新同步 8080 的原连接，确认 H3 的新绑定含 `image`，保留精确模型名、原 Key、映射和 New API 价格。同步失败保留旧记录并显示原因。
5. 核验纯文字、首帧连线、首尾帧、`@` 参考图及模型支持的其他引用；先只读报价，之后才执行获授权的真实生成。

退出条件：相同 H3 图片用例不再被错误的文字能力拦截；费用确认可见；新绑定用于新请求，历史任务继续使用原快照。已有源码补丁完成不等于本阶段完成。

### 阶段 B：补齐 Wan 及其他已有适配的能力和估算

责任范围：`D:/newapi/controller/canvas_bridge.go` 与相应测试、现有插件能力依据、`packages/providers`、`apps/api/src/billing-submission.ts` 及报价/同步测试。

1. 首先针对 `wan3.0-video` 和 `wan3.0-video-prime`，按实际 Key 可达渠道、插件、上游模型和协议建立输入清单。百炼与 Moon 的同名模型不能共用未经确认的参数限制。
2. 复用现有 Provider 与插件映射，明确支持的媒体、角色、模式、数量和组合；目录、画布预检、费用预估与真实发送采用一致含义。不要把所有模型统一标成只支持文字，也不要统一标成支持全部媒体。
3. 同一对外模型可能走多条渠道时，声明可执行路由共同支持的能力；确需某个特定渠道能力时，先确认现有路由约束，不能允许预估和实际生成走不兼容协议。证据不足的模型显示具体缺口。
4. 同步能力和费用估算一起修复。按实际输入携带必要的媒体类型、角色、数量和原价格规则需要的时长等信息；复用最终生成的资产版本去重与角色映射，避免漏算或重复计算。
5. New API 继续调用原插件用量提取与计费表达式，不在 Canvas 复制另一份收费公式。H3 的 15 秒输入视频预留是原插件规则，不能直接套给 Wan 等其他模型；缺少所需计量且上游没有可靠预算规则时明确阻止报价。
6. 对新字段做两端兼容验证。旧宿主不支持时提示配套更新，不能丢弃媒体字段退回纯文字估算。未知能力不要靠移除校验或清空字段放行。
7. 再盘点文字、图片、Seedance、Grok 等已有成功证据的模型与输入组合，只修复本次同步引入的退化；新的供应商或未适配协议进入独立待办。

退出条件：每个对外开放的组合都有“目录声明、预检、请求字段、预估用量”对照和回归证据；各模型分别验收，不将 H3 通过外推为所有视频通过。

### 阶段 C：恢复直接选择模型的体验

责任范围：`apps/api/src/model-marketplace.ts`、模型解析、连接管理、`apps/web/src/workspace/NodeQuickEditor.tsx` 及广场相关组件。

1. 沿用现有“保存/刷新连接后同步托管模型”的入口，修复已适配模型未进入可选目录的原因。合同、能力和 New API 价格齐全时自动建立可用绑定，用户无需重复手工导入或定价。
2. 广场展示原站价格；画布选择器明确区分“能调用”和“仅目录可见”，不能把公开价格目录当成当前 Key 的调用权限。受阻项直接说明连接失效、协议未适配、输入不支持或报价不可用等具体原因。
3. 所有已保存的可用 Key 均可选择，同名模型按连接和 Key 尾号区分。调用固定使用本次所选 Key，禁止静默改为全局 Key 或其他便宜渠道。
4. 旧节点已有有效平台 ID 时保持不变；只有旧别名/连接引用时，按原连接、精确模型 ID 和媒体类型唯一匹配。无法唯一匹配或原连接已删除时提示重选，保留提示词、素材和节点参数。
5. 复用稳定平台身份、版本绑定和现有同步逻辑，不再建第二套模型注册系统。管理员主动暂停或删除的项目不能因恢复计划自动重新上架；历史任务、报价和账单不被同步重写。

退出条件：用户从画布即可选中原连接下的模型；更换 Key、刷新目录、打开旧项目后不误绑；不再出现模型实际可用却因未解析的托管身份而统一报“没有对应的已上架平台模型”。

### 阶段 D：完成费用与调用闭环验收

责任范围：Web 费用确认、API 提交、Worker 发送/轮询/归档和账务处理。

- 统一验证普通生成、批量、工作流、重试、优化和反推的确认流程，恢复原任务只查询原身份，不当作新生成。
- 确认报价覆盖每个实际执行节点；中间产物未确定且无可靠预算时说明是哪一项无法预估，不笼统报告“模型不可用”。
- 检查弹窗文案，明确显示这是 New API 估算得到的最高授权额，最终按账单结算；不把广场单价当成带素材、分组和参数的本次总价。
- 在用户授权的模型、输入组合、金额范围和次数内进行真实烟测，记录原请求/任务 ID、结果归档和最终回执。请求结果不明时恢复查询，不自动再次发送可能扣费的 POST。

退出条件：用户确认前零生成请求；确认后每个收费项仅执行一次；最终结果和账单可关联；失败、取消、回执延迟和恢复均不会重复扣款或产生无法解释的冻结。

## 5. 验收清单

| 用例                         | 必须证明的结果                                      | 证据方式                                     |
| ---------------------------- | --------------------------------------------------- | -------------------------------------------- |
| H3 纯文字与图片提及          | 两种输入均按真实能力进入报价，图片保留正确角色      | API 回归、运行环境只读报价、授权后的真实生成 |
| 视频首帧、首尾帧、多参考素材 | 只开放各模型真实支持的组合，连线与 `@` 两条入口一致 | 序列化回归与逐组合验收                       |
| 两个 Wan 模型                | 依据实际插件声明能力和预估，不能套 H3 参数          | 目录/请求/计费对照及授权烟测                 |
| 两个 Key 下的同名模型        | 页面可区分；报价、生成和回执使用同一 Key            | 合成凭据隔离测试，真实凭据仅只读核对         |
| 旧项目和节点                 | 原模型可唯一恢复；失效连接明确提示，无静默换绑      | 数据副本兼容测试与 PC Web 烟测               |
| 费用确认、取消、余额不足     | 显示每项与总上限；未确认不创建任务、不冻结余额      | Web/API/账务回归及生成调用计数               |
| 报价过期或请求变化           | 必须重新报价确认，不自动接受新金额                  | Web/API 回归                                 |
| 媒体计量和 DAG 去重          | 同版本同图不重复，版本不同不合并；估算不漏执行节点  | 冻结快照、请求体和报价测试                   |

| 超时、恢复、重复点击         | 查询原任务，保留幂等身份，不重复创建生成或收费项    | 隔离 Worker/API 故障恢复测试                 |

## 6. 数据、发布与回退

- 本轮文档没有数据库迁移、价格写回、运行配置或代码变更。后续优先复用已有模型、绑定和价格表；同步创建新绑定版本，不原地改写历史快照。
- 生产更新、实际改价、删除/覆盖及付费生成不因本计划自动获授权。上线时再按已准备好的镜像、备份、差异和验收范围取得相应授权。
- 发布前记录在途任务和未结算冻结，备份数据库、资产及加密凭据所需密钥，核验备份能读取；备份不得写入源码仓库或输出真实 Key。
- 配套更新期间控制新提交入口，旧任务由能理解原快照的 Worker 处理。先更新并核验 New API 宿主，再更新 Canvas、同步目录并验证报价；不能让新 Canvas 使用旧宿主进行媒体估算。
- 回退时暂停新增调用，恢复已记录的兼容镜像并核对/重同步目录。新绑定不自动随镜像回退消失，必须确认不会继续宣称旧宿主不支持的能力。保留在途任务、回执、钱包流水，不用旧数据库备份覆盖新账务记录。
- 保留 `docs/resource-input-compatibility.md` 的原有用户改动；不得把该文件混入本轮提交。更换 URL、Key 或价格同步不得删除历史模型、项目、素材和账单。
