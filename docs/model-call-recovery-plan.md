# 模型调用恢复计划

更新时间：2026-09-20。优先级：P1。状态：计划优化完成，功能实施和运行环境验收待执行。本轮范围仅为本文档；下文新增的执行要求不是已实现功能，也不代表已部署、改价、删除数据或发起付费生成。

## 1. 建议与完成目标

建议保留已确认的人民币钱包和 New API 原价，修复连接、能力同步及调用绑定，让用户恢复“选连接和模型、放入素材、确认费用、生成”的操作。不再要求管理员为同一批 New API 模型重复填写价格、输入能力或逐个手动上架。

“像以前一样正常调用”按具体模型和输入组合验收：现有连接中的已适配模型可以选择；过去支持的文字、首帧、首尾帧和参考素材能正确送到对应接口；任务可查询、归档并打开结果。保留所有已保存 Key 的选择入口和安全尾号，不随全局活动 Key 切换而改用其他连接。

本方案优先恢复当前受阻的 `MiniMax-H3`、`wan3.0-video`、`wan3.0-video-prime`，同时检查已有成功证据的文字、图片及其他视频调用。公开广场里仅有名称和价格、但尚无已确认调用协议的模型，不列为已经可调用。

此前讨论的“移除画布钱包和模型广场”是另一条产品路线，会同时改变费用确认、任务授权、历史节点引用和账务处理。它不是修复本次图片拦截的必要条件，本计划不执行该删除。若以后改为仅由 New API 扣费，应单独设计调用与账务解耦，不能直接删表或关闭 Worker 授权检查。

完成标准分为三层，分别记录，不用前一层替代后一层：

| 层次           | 完成依据                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| 代码修复完成   | 各模型的目录声明、预检、请求映射和计费输入一致，隔离回归及构建通过                                                |
| 运行环境已更新 | 确认两端实际运行版本和插件，重新同步后新绑定生效，PC Web 费用确认可用                                             |
| 调用恢复已验收 | 当前三款视频模型各自拟开放的组合完成获授权生成、轮询、归档和账单核对；覆盖普通生成、旧节点、两个 Key 和一个工作流 |

已有实现先核对再复用，不重新开发钱包、连接管理或报价系统。没有真实上游证据的组合继续标为待验证；某个组合失败不代表整个模型或所有媒体都不可用。

### 故障定位与同步核对

先定位失败阶段，再决定修复动作。服务健康、价格可见、Key 中有模型、能力已同步、真实调用成功是不同证据。

| 失败位置或现象             | 需要核对的事实                                            | 处理要求                                                       |
| -------------------------- | --------------------------------------------------------- | -------------------------------------------------------------- |
| 广场能搜索，画布没有可用项 | 公开定价目录与当前 Key 鉴权目录是否一致，原连接是否仍有效 | 按所选连接同步和解析，不把公开价格当作权限证明                 |
| 没有对应的已上架平台模型   | 平台 ID、原连接、精确模型名、发布状态及旧引用是否唯一匹配 | 返回具体缺项；已删除、暂停或歧义项不能静默换绑                 |
| `missing_profile`          | 实际插件版本、模型映射及注册的提交/查询协议               | 核实宿主和插件，不能靠改显示名称修复协议                       |
| 不支持 `image` 提及        | 当前鉴权目录和激活绑定分别声明什么，真实插件支持什么      | 目录正确而绑定陈旧则同步；目录也错误则补适配，不能直接清空限制 |
| 无法报价或余额不足         | 估算接口、所需媒体计量、报价有效期及付款账户              | 明确属于费用阶段，不笼统显示模型不可用，不跳过报价发送         |
| 已提交后失败               | 原请求/任务 ID、上游响应、素材读取、轮询和归档状态        | 查询原任务定位，不重复生成；本地预检通过不能证明上游已成功     |

每次同步验收都比对“New API 当前目录 → Canvas 激活绑定 → 画布选择结果”，记录精确模型 ID、连接内部身份及版本、合同、能力、绑定版本和同步时间。沿用现有字段及脱敏证据，不为本次修复新建诊断平台。只有上游目录读取成功且新绑定可读回时才算同步成功；失败保留原数据并标记旧结果，不能显示为本次已更新。

现有资源提及校验拒绝与显式能力限制冲突的输入，缺省声明不是一律拒绝。本次修复应纠正错误的明确声明，不把缺省值解释为“全部支持”，也不扩大成对所有缺省模型的新增拦截。

## 3. 当前是否在发送前提示费用

**是。当前已经实现发送生成请求前的费用确认，显示的是根据估算得到的人民币预算上限，不是最终精确账单。**

现有顺序如下：

```text
点击生成
  → 校验模型、连接、输入素材与参数
  → 使用原 Key 向 New API 请求费用估算
  → 显示每项最高费用、合计最高费用、可用余额、报价有效期
  → 用户点击“确认并生成”
  → 原子创建任务并冻结本次授权额度
  → Worker 向 New API 发送生成请求
  → 结果交付后读取原请求的最终账单，结算并释放多余冻结
```

估算会访问 New API 的 `POST /v1/canvas/estimate`，但不调用生成接口，不预扣生成费用。Canvas 此时只保存报价，没有冻结钱包，也没有创建生成任务。上述 H3 图片能力错误在报价前发生，因此当时还看不到后面的费用弹窗。

验证时区分三类操作：读取目录是只读；创建报价会保存报价记录，称为“非付费报价验证”；确认生成会冻结额度并可能触发上游扣费。不能把保存报价称为完全不写数据的只读检查。

| 项目       | 当前实现                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| 弹窗内容   | 模型名称、计费方式、数量、每项最高人民币费用、合计、可用余额及到期时间                                        |
| 确认按钮   | `确认并生成 · 最高 ¥…`；确认前取消、关闭页面或切换账户均不提交新生成                                          |
| 价格来源   | New API 托管模型通过原 Key、精确模型和输入参数预估，复用上游原价格规则；无需在画布另填价格                    |
| 报价有效期 | 本地五分钟与上游有效期取较早者；过期要重新报价并再次确认                                                      |
| 请求变化   | 已保存的报价绑定模型、连接版本、参数和冻结输入；不匹配则拒绝，不能拿旧报价执行新请求                          |
| 余额不足   | 确认按钮禁用；后端仍原子校验余额，避免并发超用                                                                |
| 估算失败   | 不创建运行、不冻结余额；明确显示原因，不把失败当成免费                                                        |
| 最终扣费   | 对于已交付的 New API 托管任务，以原请求最终净 quota 按报价时冻结的换算规则结算，Canvas 扣款不超过用户确认上限 |
| 回执未完成 | 保持待核实，继续查询原任务/回执；不把估算冒充实际费用，不重新发起生成                                         |

示例仅说明规则，不代表某个模型的实际价格：确认最高 ¥1.00，最终费用 ¥0.80，则结算 ¥0.80、释放 ¥0.20。若上游实际费用超过 ¥1.00，Canvas 钱包仍按 ¥1.00 封顶，差额由平台承担。这个上限约束 Canvas 钱包，不能保证 New API 本身不会扣除更高的上游费用；报价也不会锁住上游之后修改的价格或分组。

已有入口：[费用弹窗](../apps/web/src/marketplace/QuoteDialog.tsx)、[报价与确认请求](../apps/web/src/marketplace/quote-client.ts)、[API 报价](../apps/api/src/billing-submission.ts)、[结算规则](../packages/domain/src/billing.ts)、[Worker 最终回执](../apps/worker/src/billing-execution.ts)。前次已核对源码、定向测试和 8080 已发布静态资源；本轮仅复核文档涉及的源码语义，没有新增实际报价弹窗或付费生成验收。

## 4. 分阶段执行

默认顺序为 A 的本地验证 → B/C 的独立修复 → D 的配套发布和验收。等待生产授权不阻止本地开发、回归和发布准备。若单独优先发布 H3，仍须完成 D 对 H3 的全部检查，Wan 等其他模型保持原有状态和待办。

### 阶段 A：复核 H3 补丁并完成发布准备

责任范围：New API 宿主版本与插件状态、Canvas API/Worker/Web 镜像、当前连接目录同步。

1. 记录双方代码提交与实际运行版本、镜像、Hailuo 生效版本、待处理任务和当前模型绑定，区分源码已更新与运行进程已更新。确认后续发布的备份、回退点和验收范围。
2. 在隔离环境重现当前图片拒绝，再使用已提交修复验证相同输入可以获得报价，且生成请求计数为零。
3. 在隔离环境核验同步新增含 `image` 的 H3 绑定，原 Key、映射、价格及历史绑定保留。New API 宿主须包含桥接修复，Hailuo 使用 1.1.4 或包含相同适配的后续版本；检查上传插件覆盖工厂版本的情况。
4. 对纯文字、首帧连线、首尾帧、`@` 参考图分别核对目录、预检、估价与序列化。模型不支持的组合保持明确拒绝，不把所有角色同时放行。
5. 输出配套发布清单：双方提交/镜像、插件、配置差异、同步入口、预计受影响模型及回退步骤；部署和真实生成放到阶段 D。

退出条件：隔离环境的 H3 图片用例可以进入费用确认，新绑定用于新请求，历史快照保持不变；配套发布内容明确。此时仅记录代码与隔离验证状态，不宣称 8080 已恢复。

### 阶段 B：补齐 Wan 及其他已有适配的能力和估算

责任范围：`D:/newapi/controller/canvas_bridge.go` 与相应测试、现有插件能力依据、`packages/providers`、`apps/api/src/billing-submission.ts` 及报价/同步测试。

1. 首先针对 `wan3.0-video` 和 `wan3.0-video-prime`，按实际 Key 可达渠道、插件、上游模型和协议建立输入清单。百炼与 Moon 的同名模型不能共用未经确认的参数限制。
2. 复用现有 Provider 与插件映射，明确支持的媒体、角色、模式、数量和组合；目录、画布预检、费用预估与真实发送采用一致含义。不要把所有模型统一标成只支持文字，也不要统一标成支持全部媒体。
3. 同一对外模型可能走多条渠道时，声明可执行路由共同支持的能力；确需某个特定渠道能力时，先确认现有路由约束，不能允许预估和实际生成走不兼容协议。证据不足的模型显示具体缺口。
4. 同步能力和费用估算一起修复。报价和生成使用同一份冻结输入，核对所选连接版本、精确模型名、协议、媒体角色/数量及价格规则所需时长；复用资产版本去重与角色映射，避免漏算或重复计算。估算的媒体描述只含必要的类型和计量信息，不包含真实素材 URL、凭据或素材正文；接口鉴权仍使用原冻结 Key。
5. New API 继续调用原插件用量提取与计费表达式，不在 Canvas 复制另一份收费公式。H3 的 15 秒输入视频预留是原插件规则，不能直接套给 Wan 等其他模型；缺少所需计量且上游没有可靠预算规则时明确阻止报价。
6. 对新字段做两端兼容验证。旧宿主不支持时提示配套更新，不能丢弃媒体字段退回纯文字估算。未知能力不要靠移除校验或清空字段放行。
7. 再盘点文字、图片、Seedance、Grok 等已有成功证据的模型与输入组合，只修复本次同步引入的退化；新的供应商或未适配协议进入独立待办。

素材传输单独验收：要求 URL 的模型必须读取到同一冻结版本的素材，不能把浏览器可访问的 `localhost`、容器内部地址或过期签名当作上游可用地址。现有 Compose 的 `MC_S3_PROVIDER_ENDPOINT` 映射到 Worker 的 `S3_PROVIDER_ENDPOINT`；实施时检查实际配置、HTTPS 地址、签名有效期和脱敏测试对象的外部 GET。只在已确认协议允许时使用 Base64 回退，不能用放开模型能力掩盖素材不可访问。

退出条件：每个对外开放的组合都有“目录声明、预检、请求字段、预估用量”对照和回归证据；各模型分别验收，不将 H3 通过外推为所有视频通过。

### 阶段 C：恢复直接选择模型的体验

责任范围：`apps/api/src/model-marketplace.ts`、模型解析、连接管理、`apps/web/src/workspace/NodeQuickEditor.tsx` 及广场相关组件。

1. 沿用现有“保存/刷新连接后同步托管模型”的入口，修复已适配模型未进入可选目录的原因。合同、能力和 New API 价格齐全时自动建立可用绑定，用户无需重复手工导入或定价。恢复调用只使用连接目录同步，不调用“同步模型与价格”写回待处理草稿，不要求额外提供管理 PAT。
2. 广场展示原站价格；画布选择器明确区分“能调用”和“仅目录可见”，不能把公开价格目录当成当前 Key 的调用权限。受阻项直接说明连接失效、协议未适配、输入不支持或报价不可用等具体原因。
3. 所有已保存的可用 Key 均可选择，同名模型按连接和 Key 尾号区分。调用固定使用本次所选 Key，禁止静默改为全局 Key 或其他便宜渠道。
4. 旧节点已有有效平台 ID 时保持不变；只有旧别名/连接引用时，按原连接、精确模型 ID 和媒体类型唯一匹配。缺少原连接、存在多个同名候选或原连接已删除时提示重选，不用当前全局 Key 填补。已有平台 ID 失效时也不能按名称换成其他商品；保留提示词、素材和节点参数。
5. 复用稳定平台身份、版本绑定和现有同步逻辑，不再建第二套模型注册系统。管理员主动暂停或删除的模型不能因恢复计划自动重新上架；历史任务、报价和账单不被同步重写。
6. 同步后的选择器重新读取服务端目录，保留所选平台身份；新报价使用新激活绑定，绑定或输入变化后的未消费报价需要重新确认。已经受理的任务仍使用原快照和凭据版本，不能为修复新请求而重绑历史任务。

同步入口：`POST /v1/admin/model-marketplace/connections/sync` 传入原 `credentialId` 处理指定连接；未传表示全部连接，应按验收范围明确选择。`POST /v1/admin/model-marketplace/newapi/sync` 会尝试写回价格草稿，不用于本次能力恢复。连接同步会更新本地目录和绑定，同样不属于只读操作。

退出条件：用户从画布即可选中原连接下的模型；更换 Key、刷新目录、打开旧项目后不误绑；不再出现模型实际可用却因未解析的托管身份而统一报“没有对应的已上架平台模型”。

### 阶段 D：配套发布并完成费用与调用验收

责任范围：两端运行环境、目录同步、Web 费用确认、API 提交、Worker 发送/轮询/归档和账务处理。

发布前完成拟发布范围的代码审查、隔离回归、运行包构建和第 6 节备份准备。执行顺序为：记录旧状态 → 更新 New API 宿主并确认插件 → 更新 Canvas API/Worker/Web → 同步原连接目录 → 读回新绑定 → 检查浏览器目录与报价 → 获授权后真实生成。每一步记录实际版本和结果，源码提交号或健康检查不能替代运行证据。

- 统一验证普通生成、批量、工作流、重试、优化和反推的确认流程。已发送节点恢复时查询原任务或回执；用户主动重试或改变输入属于新请求，需要重新报价确认，不能混入旧任务恢复。
- 确认报价覆盖每个实际执行节点；中间产物未确定且无可靠预算时说明是哪一项无法预估，不笼统报告“模型不可用”。
- 检查弹窗文案，明确显示这是 New API 估算得到的最高授权额，最终按账单结算；不把广场单价当成带素材、分组和参数的本次总价。
- 覆盖旧 Canvas/新 New API、新 Canvas/旧 New API 及浏览器缓存旧页面的组合。允许的兼容范围须有测试；不兼容时给出明确更新提示，不能丢弃媒体字段继续发送。先排除版本混用再判断模型不支持。
- 在用户授权的模型、输入组合、金额范围和次数内进行真实烟测，记录原请求/任务 ID、结果归档和最终回执。请求结果不明时恢复查询，不自动再次发送可能扣费的 POST。

退出条件：用户确认前零新增生成请求；确认后同一收费项不重复发送；最终结果和账单可关联；失败、取消、回执延迟和恢复均不会重复扣款或产生无法解释的冻结。DAG 恢复可能首次执行已授权但尚未发送的下游节点，不能把“恢复不重发已发送项”写成“恢复过程绝不新增任何 POST”。
