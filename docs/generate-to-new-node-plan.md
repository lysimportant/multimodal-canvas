# 生成即分叉：结果承载新节点开发实现步骤

## 1. 目标与范围

把"生成结果写回当前节点"改成**默认写进一个新建的子节点**，并且**只有用户点"生成"这一处会自动执行**。

- 任何节点（图片、文字、音频、视频）点"生成"时：新建一个子节点承载结果，并立即提交运行。
- 父节点**完全保留**：提示词、模型、凭据、参数、推理强度、位置、尺寸、节点 ID、回显一个字都不改，因此同一个父节点可以反复生成多个子节点。
- 子节点**只承载新结果**：不继承父节点的资产与参考资源，也不显示父节点的图片。
- 图片节点（上传的或从资产添加的）**直接就是图生图 edits 节点**，不需要先点"修改图片"。

本任务面向 PC Web 画布，包含画布数据、前端交互、运行提交、导入导出与测试方案。移动端专用布局、批量多图编辑、局部蒙版编辑列为后置事项。

### 1.1 与既有"修改图片"流程的关系

已有的 `imageEditSource` / `input:imageEdit` / Provider 能力门禁全部沿用，不新造概念。本任务把它从"一个按钮触发"升级为"所有节点生成时的默认落点"。

---

## 2. 不可违反的边界

- **父节点零写入**：不得写回显、不得写 `assetId` / `contentUrl` / `resultAsset` / `manualOutput` / `runStatus`，不得改位置与尺寸。
- **子节点必须使用全新节点 ID**，并通过显式边连接父节点；图片类子节点必须带 `imageEditSource`，不得依赖隐式推断。
- **子节点不得继承父节点的资产字段**：`assetId`、`contentUrl`、`mimeType`、`resultAsset`、`manualOutput`、`manualOutputRunId`、`resourceRefs`、`runStatus`、`runProgress`、`runError` 一律不带。
- **唯一的自动执行点是"生成"**：添加资源、打开编辑器、切换模型、修改参数、画布加载——都不建节点、不发请求。
- **没有提示词不得发请求**：无提示词时既不建节点也不提交，向用户说明原因。
- **一次点击只产生一个子节点**，不做无限自动分叉；子节点上再点生成才产生下一环。
- **不自动重试**：`524` 这类"结果未知"的错误不得重发，也不得切换端点或模型。
- 运行前冻结来源资产的 `assetId + version`；来源后续产生新版本不改变已创建运行。

---

## 3. 用户流程与状态

### 3.1 主流程

```text
从资产添加图片 / 上传图片
  -> 画布 +1 节点，没有子节点、没有请求            （R1）
  -> 点击节点，只打开编辑器，仍然没有请求             （R1）
  -> 输入"换成夜景"，只改节点数据，仍然没有请求        （R1）
  -> 点击“生成”
       · 新建子节点（全新 ID）
       · 写 imageEditSource 冻结这张图
       · 连 input:imageEdit 显式边
       · 立即提交运行（提示词与图片一起进接口）        （R2/R3）
       · 父节点一个字段都不写                        （R5）
  -> 子节点显示新图，父节点还是原来那张
  -> 父节点可以再次点生成，得到第二个、第三个子节点      （R5）
  -> 子节点本身也是“有图片的节点”，可以继续生成下一环
```

### 3.2 状态与提示

| 状态       | 表现                                                           |
| ---------- | -------------------------------------------------------------- |
| 无提示词   | 生成按钮禁用并提示"请先填写提示词"；不建节点、不发请求         |
| 提交中     | 子节点显示运行中状态，父节点保持可编辑                         |
| 成功       | 子节点回显结果；提示"`<子节点名>` 已完成"                      |
| 失败       | 父节点不变；子节点保留并显示错误，可**原地重试**，不重复建节点 |
| 建节点失败 | 回滚本次节点与边，不留下半成品，给出可操作错误                 |

## 4. 数据模型设计

1. 在 `packages/domain/src/index.ts` 新增 `resultTargets = ['sameNode', 'newNode']` 与 `resultTargetSchema`。
2. `nodeDataSchema` 增加可选字段 `resultTarget?: 'sameNode' | 'newNode'`。
   - **可选**语义：缺省按"新节点"处理；旧画布不迁移、不改写。
   - 缺省值由**应用层**决定，不写进 schema 的 `.default()`，避免所有旧画布节点在解析时被补字段。
3. 保留 `sameNode` 作为数据层回退路径（覆盖当前节点回显，即现有行为），但**本期不提供界面开关**；界面上不存在入口，用户不会误触。
4. `resultTarget` 必须随 `toCanvasDocument`、导入导出、剪贴板与历史记录一起保存；`fromCanvasDocument` 原样恢复。
5. 与视频既有的 `completionAction` 明确分工，互不覆盖：
   - `completionAction`：**视频成功之后**对末帧做的动作（预览、建资产、追加图片节点、填入指定节点）。
   - `resultTarget`：**提交前**决定本次结果写当前节点还是写新子节点。
6. 子节点继承与不继承的字段清单（写成常量与测试断言，避免以后被"顺手"改掉）：

| 类别   | 字段                                                                                                                                                     |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 继承   | `mediaType`、`modelAlias`、`credentialId`、`parameters`、`inferenceStrength`、`videoMode`                                                                |
| 不继承 | `assetId`、`contentUrl`、`mimeType`、`resultAsset`、`manualOutput`、`manualOutputRunId`、`resourceRefs`、`runStatus`、`runProgress`、`runError`、`stale` |
| 新写入 | `label`、`mode: 'generate'`、图片类的 `imageEditSource`                                                                                                  |

## 5. 前端实施步骤

### 5.1 App 运行分发

- 把现有 `runNode()` 主体抽成 `runNodeInPlace(node)`：**请求体、轮询、通知逻辑一行不改**，只把"对哪个节点运行"变成参数。
- `runNode()` 改为纯分发：
  - `resolveResultTarget(node)` 显式值优先，否则缺省"新节点"。
  - `newNode` → `runNodeAsNewChild(parent)`
  - `sameNode` → `runNodeInPlace(parent)`（回退路径）
- 新增 `runNodeAsNewChild(parent)`：
  1. 校验父节点存在、已启用、**有可运行提示词**；无提示词直接提示并返回，不建节点。
  2. 计算位置：`getNodePlacementRightOf(parent, nodes, getNewNodeDimensions(mediaType))`，碰撞继续向右/向下，**不动父节点尺寸**。
  3. 建子节点：新 ID、`mode: 'generate'`、继承模型与参数、**不带任何资产字段**、标签沿用 `createUniqueNodeLabel('<父节点媒体类型><模式>节点', 现有标签)`。
  4. 图片类子节点：写 `imageEditSource = { sourceNodeId: parent.id, assetId: 父图资产, version?, sourceKind }`，并构造 `input:imageEdit` 显式边。
  5. 其它媒体类型：按现有首选角色构造显式边（文字→`input:content`，音频→`input:prompt`，视频→父节点输出到 `input:firstFrame`）。
  6. **同一次历史事务**：`rememberHistory()` → 追加节点与边 → `appendNodesAndSelect([child])` → 打开子节点的快速编辑器 → 置画布 dirty。
  7. **紧接着立即运行**：直接提交子节点运行（提示词 + 资源一起进接口），不经过第二次用户点击。
  8. 父节点在以上任何一步都**不被写入**。
- `handleCreateImageEditNode` 改为复用 `runNodeAsNewChild`，消掉两份重复的建节点逻辑。
- 失败处理：`runNodeAsNewChild` 内若建节点/连线校验失败 → 回滚并提示；若运行提交失败 → 保留子节点与边，提示可原地重试。

### 5.2 节点入口

- `AssetNode`：有回显的图片节点（含 `mode: 'source'`）在未运行、未保存中时显示图生图入口；文案与可访问名称保持"修改图片"，避免与"生成"混淆。
- 父节点在运行期间保持可编辑（提示词、模型、参数），因为它的配置对下一次生成仍然有效。
- 生成按钮在无提示词时禁用，`title` 说明原因。

### 5.3 快速编辑器

- 编辑器的运行按钮沿用现有 `onRun` 入口；本任务不新增界面开关。
- 子节点被自动选中并打开编辑器时，编辑器不显示父节点图片作为参考图（`connectedAssets` 只反映真实入边，图片类子节点的入边是 `imageEdit`，由只读来源图区域展示）。
- 父节点编辑器在生成后**不清空、不关闭**。

---

## 6. 运行链路

1. 运行快照必须包含不可变的父节点与冻结的 `assetId/version`（沿用现有 `resolveRunAssetRefs` 按版本冻结）。
2. 图片类子节点继续走 `imageEdit` 角色与 `imageEditCapability` 能力门禁；模型未声明 `imageEdit` 时，在创建 Run 之前返回 `IMAGE_EDIT_UNSUPPORTED`，**零上游请求**。
3. 子节点结果写入子节点的 `resultAsset`；父节点成功状态与资产不被替换。
4. 单次点击只提交一次运行；`524` 等结果未知错误不自动重试。

---

## 7. 兼容与迁移

- 旧画布没有 `resultTarget` 时按"新节点"处理；不自动推断历史节点曾经的结果落点。
- 导入遇到非法 `resultTarget` 时按 schema 报错并附 issues，不丢弃节点或边。
- 撤销/重做与画布导出必须保持父子边、`imageEditSource` 与版本引用的一致性。
- 视频 `completionAction` 的既有语义不变。

---

## 8. 测试与验收

### 单元与组件测试

- 领域 schema：`resultTarget` 取值校验、旧画布缺省、导入导出与剪贴板保留。
- 画布（`canvas-editor.test.tsx`）：
  - 添加资源、打开编辑器、改参数 → **0 节点新增、0 请求**
  - 无提示词点生成 → **0 节点新增、0 请求**
  - 点生成 → 恰好 +1 节点、+1 条显式边、父子 ID 不同、**恰好 1 次请求**且请求体含提示词
  - **父节点字段逐项深比较不变**（含位置、尺寸、`data` 全字段）
  - 子节点**不含** `assetId`/`contentUrl`/`resultAsset`/`manualOutput`
  - 子节点继承模型、参数、推理强度
  - 连续两环：孙节点 `imageEditSource` 指向子节点，形成链
  - 子节点运行失败：父节点不变、可原地重试、不再新增节点
  - 模型未声明 `imageEdit` → 运行按钮禁用并给出原因
  - 同一父节点连续生成两次 → 两个不同子节点，父节点仍不变
- 定位工具：子节点避开已有节点，父节点尺寸不变。

### Playwright 冒烟

- Mock 栈：四类节点点生成后确认"结果落在新建子节点"且父节点尺寸不变；控制台无错误。
- **需要改写的既有断言**（行为变更的必然结果，产品逻辑零改动）：
  - `apps/web/e2e/smoke.spec.ts` 四类节点用例内的**结果元素断言**：由"原节点内"改为"新建子节点内"。
  - 同一用例块的**节点数断言**：由"数量不变"改为"+1"。
  - 5 处 `'<节点名> 已完成'` 提示断言**不需要改**：子节点标签为 `<基名> 2`，`hasText` 包含匹配仍然命中。

### 验收标准

- 用户点一次生成即可拿到一个承载新结果的独立节点，父节点原封不动。
- 未输入提示词时不会创建节点，也不会产生任何上游请求。
- 有图片的节点无需手动连线即可图生图，且可以连续改图。
- 撤销一次即整体回滚该次分叉（节点 + 边 + 运行）。

## 9. 风险与后置事项

- 连续分叉会让画布节点数增长较快；本期依靠撤销与手动删除控制，不做自动清理。批量节点管理与自动布局列为后置事项。
- 四类节点统一分叉后，文字/音频节点的子节点没有继承父节点内容，属于设计选择（父节点保留、子节点只承载新结果）；若将来需要"子节点继续用父节点提示词"，应作为显式选项引入，不能在缺省路径上隐式继承。
- 是否在界面上暴露"结果放到新节点 / 当前节点"开关为后置事项；数据字段已经预留，届时不需要再改数据结构。
- 多参考图、局部重绘（mask）、连续编辑的版本链模型仍不在范围内。
