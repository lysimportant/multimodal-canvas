# 生成到新节点：覆盖当前回显与分叉承载

## 0. 已确认的产品口径

本期不是把「生成」改成默认分叉。界面上要有两个明确按钮，落点由用户点哪一个决定：

1. **生成**（已有）：在当前节点上提交运行，成功后**覆盖原来的回显资源**。空节点第一次生成也走这条路径。
2. **生成到新节点**（新增）：用当前节点同一套生成配置再跑一次，结果写到新建子节点；当前节点的提示词、模型、参数、位置、尺寸、节点 ID 和回显全部保留。这个按钮**只在生成节点已经有回显内容时出现**。

「修改图片」仍是第三条独立路径：只给已有图片回显的节点，新建空的图生图编辑节点并打开编辑器，**不自动运行**。不要把它和「生成到新节点」合并。

仓库里目前还没有对应功能分支；本文是开发前的实现计划，不是已完成实现。

---

## 1. 目标与范围

在 PC Web 画布上为四类生成节点（图片、文字、音频、视频）增加「结果写到新节点」入口，同时保留现有原地生成。

- 无回显：只能看到「生成」，结果写回当前节点。这是空节点、首次生成、失败且没有旧产物时的唯一路径。
- 有回显：同时看到「生成」和「生成到新节点」。前者覆盖当前回显，后者新建子节点承载本次结果。
- 两次点击的**生成语义必须等价**：同一提示词、模型、凭据、参数、推理强度、视频模式、入边输入，以及当前节点已有的图片编辑来源。差别只在结果写到哪个节点。
- 不要把普通「生成」升级成图生图；不要让视频「生成到新节点」偷偷改成首帧/图生视频。
- 唯一会自动建节点并立刻发请求的入口是用户点击「生成到新节点」（以及等价的右键菜单项）。添加资源、打开编辑器、切换模型、修改参数、画布加载都不建节点、不发请求。

本任务包含画布数据、前端交互、运行提交与测试。移动端专用布局、批量多图编辑、局部蒙版编辑、自动清理分叉节点列为后置事项。

### 1.1 与既有「修改图片」流程的关系

| 入口 | 何时出现 | 做什么 | 是否立刻运行 |
| --- | --- | --- | --- |
| 生成 | 所有生成节点 | 原地提交，覆盖当前回显（无回显则第一次写出回显） | 是 |
| 生成到新节点 | 生成节点**已有回显** | 复制当前生成配置到新节点并立刻运行，父节点回显不动 | 是 |
| 修改图片 | 图片节点已有回显（含来源节点） | 新建空的图生图节点，写入图片编辑来源与 `input:imageEdit`，打开编辑器等用户填写新提示词 | 否 |

「修改图片」继续使用现有 `handleCreateImageEditNode`、`imageEditSource`、`input:imageEdit` 与 Provider `imageEdit` 门禁。本期不把它改成立刻运行的分叉函数，也不要求用户先点「修改图片」才能「生成到新节点」。

## 2. 不可违反的边界

- **「生成」行为不变**：现有原地运行仍对当前节点发 POST，结果仍写当前节点。不得改默认落点，不得改写既有冒烟里「结果在原节点内 / 节点数不变」的断言。
- **「生成到新节点」才分叉**：父节点零写入，不得改回显、assetId / contentUrl / resultAsset / manualOutput / runStatus、位置与尺寸。
- **子节点必须使用全新节点 ID**。不要为了「看起来像谱系」而额外连一条会进入运行快照的父到子输入边。
- **子节点不得继承父节点的产物字段**：资产 ID、内容地址、MIME、结果资产、手动输出、运行状态、进度、错误、过期标记一律不带。
- **生成语义等价**：子节点必须继承提示词文档/提示词、资源引用、模型、凭据、参数、推理强度、视频模式、视频完成动作，以及父节点已有的图片编辑来源；并复制父节点现有入边（同源、同角色、新 target）。禁止给图片子节点凭空写图片编辑来源，禁止给视频子节点凭空连首帧边。
- **来源节点不出现该按钮**：来源模式不能直接运行；图片来源节点继续只用「修改图片」。
- **没有可运行提示词不得发请求**：两条生成按钮都禁用并说明原因；「生成到新节点」在无提示词时**不建节点**。
- **一次点击只产生一个子节点**。子节点失败后原地重试，不重复建节点。
- **不自动重试**：`524` 这类结果未知错误不得重发，也不得切换端点或模型。
- 运行前冻结来源资产的资产 ID 与版本；来源后续产生新版本不改变已创建运行。

## 3. 用户流程与状态

### 3.1 回显判定

「已有回显」与节点当前能否展示产物一致，不看「曾经跑过」：

- 只对生成模式显示「生成到新节点」。
- 有可展示产物：结果资产能解析出内容地址，或节点上已有资产 ID 加内容地址（含手动输出仍在展示的产物）。
- 失败但还留着旧回显：按钮要出现，这正是「保留旧图、新结果放到旁边」的场景。
- 从未成功、没有产物、产物缺失：不出现该按钮。
- 当前节点忙碌或停用：按钮可见但禁用，与现有「生成」一致。

建议在 `packages/domain/src/index.ts` 增加 `nodeHasEchoPreview(node)`，与 `isImageEditSourceNode` 并列，供编辑器、右键菜单和测试共用。不要把「有回显」写成「有图片编辑来源」或「图片节点」。

### 3.2 主流程

```text
新建空的图片/文字/音频/视频生成节点
  -> 编辑器只有「生成」，没有「生成到新节点」
  -> 点「生成」：0 个新节点，结果写回当前节点

当前节点已经有回显
  -> 编辑器同时出现「生成」和「生成到新节点」
  -> 点「生成」：仍 0 个新节点，当前回显被新结果覆盖
  -> 点「生成到新节点」
       · 新建子节点（全新 ID）
       · 复制生成配置、提示词、入边
       · 立即提交子节点运行
       · 父节点回显与字段都不写
  -> 子节点显示新结果，父节点还是原来那份回显
  -> 父节点可以再次点「生成到新节点」，得到第二个、第三个子节点
  -> 子节点自己有回显后，也可以再分叉

图片节点已有回显时，「修改图片」仍然可用
  -> 只建空的图生图节点并打开编辑器，不发请求
  -> 与「生成到新节点」互不替代
```

### 3.3 状态与提示

| 状态 | 「生成」 | 「生成到新节点」 |
| --- | --- | --- |
| 无回显 | 可见；无提示词则禁用 | 不渲染 |
| 有回显、无提示词 | 禁用，title 说明原因 | 可见但禁用；点击不建节点、不发请求 |
| 提交中 | 当前正在跑的那条路径显示忙碌 | 同一节点上两条按钮都禁用，避免并发双跑 |
| 原地成功 | 当前节点回显更新 | — |
| 分叉成功 | — | 子节点回显结果；提示「`<子节点名>` 已完成」；父节点回显不变 |
| 分叉后运行失败 | — | 父节点不变；子节点保留并显示错误，可原地重试，不重复建节点 |
| 建节点/连线失败 | — | 回滚本次节点与边，不留下半成品 |

## 4. 数据模型设计

本期**不**给节点数据增加结果落点字段，也**不**把缺省值改成新节点。

原因：落点是一次点击的动作，不是节点上需要持久化的默认配置。若写入可选字段且应用层缺省为新节点，旧画布点「生成」会被静默改成分叉，这与产品口径相反。

运行分发用函数参数即可，例如 `runNode(node, target = 'sameNode')`。不要把该参数存进画布文档、导入导出或历史快照。旧画布零迁移。

与视频完成动作的分工不变：

- 视频完成动作：视频成功之后对末帧做的动作。
- 本次两个按钮：提交前决定结果写当前节点还是写新子节点。

### 4.1 子节点字段清单

写成常量与测试断言，避免以后被顺手改掉。

| 类别 | 字段 |
| --- | --- |
| 继承（保证同一次生成语义） | mediaType、mode=generate、modelAlias、credentialId、parameters、inferenceStrength、videoMode、completionAction、prompt / promptDocument、resourceRefs、父节点已有的 imageEditSource |
| 不继承（产物与运行态） | assetId、contentUrl、mimeType、resultAsset、manualOutput、manualOutputRunId、runStatus、runProgress、runError、stale |
| 新写入 | label（createUniqueNodeLabel(父节点 label)）、全新 id |

入边：按父节点现有边复制，来源、句柄、角色不变，目标改为子节点 ID。没有入边就不要造边。

## 5. 前端实施步骤

### 5.1 App 运行分发

- 现有 `runNode(node)` 抽成明确的原地路径 `runNodeInPlace(node)`：**请求体、轮询、通知逻辑一行不改**。
- `runNode(node, target = 'sameNode')` 只做分发：
  - `sameNode` 走原地运行。键盘 R、命令面板「运行」、编辑器「生成」、右键「开始生成」全部走这里。
  - `newNode` 先确认 `nodeHasEchoPreview`；不满足则提示「当前没有可保留的回显，请直接生成」，不建节点。
  - 再走 `runNodeAsNewChild(parent)`。
- 新增 `runNodeAsNewChild(parent)`：
  1. 校验父节点存在、不是来源节点、已启用、有可运行提示词；否则提示并返回。
  2. 计算位置：`getNodePlacementRightOf(parent, nodes, getNewNodeDimensions(mediaType))`，碰撞继续向右/向下，**不动父节点尺寸**。
  3. 建子节点：新 ID、按 4.1 继承字段、**不带任何产物字段**。
  4. 复制父节点入边；校验每条边。任一条非法则整次回滚。
  5. **同一次历史事务**：记下历史 → 追加节点与边 → 选中子节点 → 打开子节点快速编辑器 → 置画布 dirty。
  6. **紧接着**对子节点调用原地运行，不经过第二次点击。
  7. 父节点在以上任何一步都**不被写入**。
- `handleCreateImageEditNode` **保持现状**，不复用 `runNodeAsNewChild`。
- 失败处理：建节点/连线失败 → 回滚并提示；运行提交失败 → 保留子节点与边，提示可原地重试。

### 5.2 节点入口

- 节点悬浮栏：**不要**再放「生成」或「生成到新节点」。图片回显节点继续只显示「修改图片」。
- 右键菜单：生成节点有回显时，在「开始生成」下增加「生成到新节点」；无回显或来源节点不渲染该项。
- 键盘快捷键 R 与命令面板「运行」保持原地生成，避免误分叉。

### 5.3 快速编辑器

- `NodeQuickEditor`（含展开对话框）的运行回调改为可区分落点，例如 `onRun: (target?: 'sameNode' | 'newNode') => void`。
- 无回显：继续一个主按钮，文案/可访问名称仍是「生成」，已有图片编辑来源时仍是「修改图片」。
- 有回显：主按钮含义不变（覆盖当前回显）；右侧增加次按钮，可见文案可用「新节点」，**可访问名称必须是「生成到新节点」**，title 说明「保留当前回显，把这次结果放到新节点」。
- 两个按钮不要都做成无文字的播放图标。主按钮保持主色，次按钮用普通按钮。
- 无提示词或参数不合法时两个按钮都禁用，title 用现有原因（请先填写提示词 / 音色等）。
- 点「生成到新节点」后会选中子节点，父节点编辑器被切走是预期；父节点数据不清空、不改回显。

## 6. 运行链路

1. 子节点运行仍走现有节点运行接口。请求体由子节点自己的提示词、模型、参数和入边生成，不新造 API。
2. 若子节点继承了父节点的图片编辑来源，继续走图片编辑角色与能力门禁；模型未声明图片编辑能力时，在创建运行之前拒绝，**零上游请求**。这只适用于父节点本来就是图生图节点的情况。
3. 普通文生图/文生视频节点的子节点不得因为「父节点碰巧有一张回显图/一段回显视频」就被改成图片编辑或首帧模式。
4. 子节点结果写入子节点的结果资产；父节点成功状态与资产不被替换。
5. 单次点击只提交一次运行；`524` 等结果未知错误不自动重试。

---

## 7. 兼容与迁移

- 旧画布零迁移。「生成」继续覆盖当前节点。
- 不新增画布字段，导入导出、剪贴板、历史记录格式不变。
- 撤销一次必须整体回滚该次分叉（节点 + 复制出来的边）。已经发出的运行不能在客户端假装没发生；节点被撤销后按现有运行/节点删除行为处理，不另做静默取消协议。
- 视频完成动作的既有语义不变。
- 既有「修改图片」测试与 Playwright 用例保持通过，不改产品逻辑去迁就分叉。

## 8. 测试与验收

### 单元与组件测试

- 领域：`nodeHasEchoPreview` 覆盖空节点、成功回显、失败但留旧回显、来源节点、产物缺失。
- 快速编辑器：
  - 无回显：只有「生成」或「修改图片」，查询不到「生成到新节点」。
  - 有回显：两个按钮都在；无提示词时两个都禁用且运行回调不被调用。
- 画布编辑器测试：
  - 空节点点「生成」→ **0 节点新增**，结果写原节点（现有断言保留）。
  - 有回显点「生成」→ **0 节点新增**，原节点回显被更新。
  - 有回显点「生成到新节点」→ 恰好 +1 节点，复制入边（无入边则 +0 边），父子 ID 不同，**恰好 1 次请求**且请求体含提示词。
  - **父节点字段逐项深比较不变**（含位置、尺寸、全部数据字段，尤其结果资产）。
  - 子节点不含产物字段，但含提示词、模型、参数、推理强度。
  - 父节点是图生图节点时，子节点复制图片编辑来源与 `input:imageEdit`，来源仍是原来的源节点，而不是把父节点自己的回显改写成新的编辑源。
  - 父节点是普通文生图/文生视频时，子节点没有图片编辑来源，也没有凭空出现的首帧边。
  - 子节点运行失败：父节点不变、可原地重试、不再新增节点。
  - 同一父节点连续分叉两次 → 两个不同子节点，父节点回显仍不变。
  - 来源图片节点：没有「生成到新节点」；「修改图片」仍只建空编辑节点、0 请求。
- 定位工具：子节点避开已有节点，父节点尺寸不变。

### Playwright 冒烟

- **不要改写**现有四类节点「点生成后结果在原节点内 / 节点数不变」的断言。
- 新增用例：节点已有回显时点「生成到新节点」，结果出现在新节点，原节点回显与尺寸不变，控制台无错误。图片节点同时覆盖「修改图片」仍可用。
- 空节点打开编辑器时，页面上不存在名为「生成到新节点」的按钮。

### 验收标准

- 空节点第一次生成，结果仍出现在当前节点。
- 已有回显时可以选覆盖，也可以选旁边新建节点；两条路径的请求语义与当前「生成」一致。
- 未输入提示词时不会创建节点，也不会产生任何上游请求。
- 「修改图片」仍然是「建空图生图节点 + 等用户填写」，不会被改成立刻运行。
- 撤销一次即去掉该次分叉产生的节点和复制边。

## 9. 风险与后置事项

- 连续分叉会让画布节点数增长较快；本期依靠撤销与手动删除，不做自动清理或自动布局。
- 本期不为谱系单独发明运行层会忽略的边角色。子节点出现在父节点右侧；若父节点本来就有入边，子节点会平行连到相同来源。
- 若以后要把「生成到新节点」做成节点级默认开关，再考虑可选的结果落点字段；缺省必须是当前节点，绝不能让旧画布改走分叉。
- 多参考图、局部重绘、把「生成到新节点」自动升级成图生图，仍不在范围内。

## 10. 相对旧稿必须丢掉的假设

实现时不要再沿用被否决的旧口径：

- 把所有「生成」默认改成分叉。
- 本期不提供界面、只留数据字段，且旧画布缺省为新节点。
- 图片节点点生成就自动变成图生图，从而不再需要「修改图片」。
- 把「修改图片」合并进立刻运行的分叉函数。
- 文字/音频子节点不继承提示词，却又要求立刻运行。
- 为了连上父节点，给视频子节点写首帧边，或给普通图片子节点写图片编辑来源。
- 改写现有四类节点冒烟，把「结果在原节点」改成「结果在新节点」。
