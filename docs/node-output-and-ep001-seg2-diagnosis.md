# 节点旧结果占用与 EP001 段2参考图排查

日期：2026-11-03。本文只记录排查结论和建议，不代表修复已实施。

## 结论

1. 旧生成资源继续显示，是前端明确保留旧结果的行为：新任务尚未产生成功资产时，节点继续使用旧的 `resultAsset`。解决方向是新一轮生成被服务端接受后，解除旧结果与节点当前输出的关联，而不是删除资产或历史记录。
2. 项目 `6c5e1e5e-e918-4071-9c8d-ca67c67b20f4` 的 `ep001-seg2`（EP001 段2 · 取证（30–60s））最新已查运行冻结了五张参考图。它在素材公网可读性预检阶段失败，记录明确说明“本次未提交生成请求”，因此不能说五张图片已经成功发送给模型。
3. 提示词文本、站内资源地址和模型实际使用的 HTTPS 素材地址是不同内容。界面没有显示 HTTPS，不能单独作为实际发送了非 HTTPS 地址的证据。本次已确认的失败是网络、DNS 或 TLS 连接不可用；具体哪一项失败仍需进一步诊断。

## 一、旧生成资源为什么仍占用节点

### 已确认的代码行为

- `apps/web/src/App.tsx:4345`：`resultAsset: resultAsset ?? node.data.resultAsset`。只有运行成功并携带新资产时才替换；排队、执行中、失败等未带新资产的更新保留旧结果。
- 同一段更新逻辑也保留旧 `resultTiming`，所以旧预览和旧结果耗时可能一起留下。
- `apps/web/src/App.tsx:4594`：生成提示词弹窗按当前展示的资产版本查询。注释明确说明新任务尚未成功时读取旧结果，不回退到最新运行。用户看到的提示词可能属于旧输出，并不属于刚点击的任务。
- `apps/web/src/canvas-utils.ts:257`：画布序列化会剔除 `resultAsset` 等运行时字段。仅清除前端字段不足以保证刷新后仍保持解绑，需要同时检查历史运行恢复流程。

### 建议解决方式（尚未实施）

将“再次点击成功”解释为服务端已接受新任务、返回有效新 Run，而不是新图片或视频已经生成完成。该解释应在实施时保持一致。

1. 接受新 Run 后，清除目标节点当前展示用的旧结果关联和对应耗时；保留资产文件、Asset/AssetVersion、历史 Run 及其结果。提交失败时保持原状态。
2. 给节点输出建立明确的运行归属或失效边界，使恢复历史、轮询、SSE、远端同步都遵循同一规则。避免仅执行一次 `resultAsset = undefined`，随后又被旧成功任务恢复。
3. 新任务成功时只绑定新输出；失败或取消时展示本次状态，旧资源仍可从历史记录或资源库查看，不自动重新占用当前节点。
4. 下游取图逻辑也应遵循解绑状态，不能只隐藏预览而仍将旧图当作当前输出。已提交任务的冻结输入保持不变；解绑后新提交的下游任务应提示缺少可用输出。
5. 手动选择输出与自动生成输出须分别处理，沿用现有 `manualOutput` / `manualOutputRunId` 保护规则，避免自动事件覆盖用户后来选中的资产。
6. 提示词入口明确区分“当前输出对应请求”和“最新运行请求”；最新运行尚未发送时直接说明，不显示旧记录冒充本次请求。

### 建议验收

- 有旧输出的节点再次提交成功后不再展示旧输出，旧资产与历史仍存在。
- 提交失败不丢失原输出；被接受后的任务失败或取消时不会悄悄恢复旧输出。
- 新任务成功绑定新资产；旧 Run 的迟到事件不能覆盖新状态。
- 刷新、重连、历史加载与远端同步不会重新挂回旧结果。
- 下游新请求不会读取已解绑旧图；已经冻结的运行输入不变。
- 手动输出不会被无关的旧运行事件覆盖。

## 三、为什么提示词不是 HTTPS

### 应区分的三层内容

| 内容 | 用途 | 是否应直接显示完整 HTTPS 签名链接 |
| --- | --- | --- |
| 提示词正文 | 描述动作、人物、场景与生成要求 | 不需要；正文不是图片传输地址 |
| 画布资源身份/冻结快照 | 记录资产 ID、版本及站内访问引用 | 不需要；站内引用不等于模型最终请求地址 |
| Worker 发送前解析的素材地址 | 让模型服务读取冻结版本的媒体 | 取决于模型合同；要求公网 URL 的合同必须提供可访问的 HTTPS 地址 |

`apps/worker/src/asset-reference-resolver.ts` 的 `providerContentUrl` 会按模型与媒体类型选择临时签名 URL 或内存 data URL。具备相应能力声明的 `newapi-video-v1` 非 GlobalStore 视频绑定会要求公网 URL；其他路径可能采用 preferred 或 data 策略。因此不能只根据模型别名断言本次命中了哪种策略。

`prisma/schema.prisma` 中 `RunRequestPrompt` 的约定明确不保存原始 HTTP body、base64、临时签名 URL 或媒体二进制。提示词记录因此不是完整网络请求抓包，也不应为了显示 HTTPS 而持久化完整签名链接。

当前尚未核验用户当时看到的具体字符串、该次运行的完整执行绑定、实际素材入口主机及部署镜像与本地代码是否完全一致。能够确认的是：这次请求因公网可读性预检失败而未发送；不能将其直接归因为“提示词不是 HTTPS”。

### 建议解决方式（尚未实施）

1. 先核对该 Run 的执行绑定与模型参考图合同，确认要求 URL、文件上传还是允许 data URL，不修改提示词正文来替代传输层修复。
2. 在 Worker 实际运行的容器网络中检查它所使用的素材入口：DNS 解析、出站连通性、证书链与域名匹配、反向代理路径、响应状态、媒体类型和签名有效期。当前错误尚不能进一步区分 DNS、网络或 TLS。
3. 若使用本站素材接口，配置模型服务可访问的真实公网 HTTPS 入口及有效签名能力；若使用对象存储，核对既有公网签名端点。`http://localhost:8080` 是本机浏览器入口，不能直接作为远端模型读取本机媒体的地址。浏览器入口为 HTTP 本身也不能证明实际素材入口错误。
4. 修复后先执行素材可读性预检，确认远端可读，再由用户明确发起新的生成。不要关闭预检、忽略 TLS 校验或把本地 HTTP 地址机械替换成 HTTPS。
5. UI 分别展示“参考图名称/版本”“本次运行发送状态”“失败阶段”。可展示脱敏后的传输方式及主机信息，但不保存或展示完整签名参数。

## 五、修复记录（2026-11-03）

### 1. 节点输出按最新运行解绑

- `apps/web/src/App.tsx` 的 `updateNodeRunState`：只有 `succeeded` 运行且带 `result.asset` 时才把结果绑定为节点当前输出；受理新运行（含 queued/running）后不再回填 `node.data.resultAsset`/`resultTiming`。提交被拒绝时不进入该函数，因此原展示保持不变。
- `apps/web/src/canvas-history.ts` 的 `restoreSnapshot`：历史快照恢复时仅成功运行可绑定结果，最新运行为失败/取消时清空展示关联；撤销/重做不会重新挂回旧结果。
- `apps/web/src/canvas-remote-sync.ts` 的 `mergeRemoteCanvasRuntime`：存在运行记录时以运行状态为准，非成功运行不再回退本地旧 `resultAsset`。
