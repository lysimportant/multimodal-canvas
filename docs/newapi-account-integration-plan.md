# New API 账号接入与画布翻新计划

更新时间：2026-09-20。主任务：P1。状态：翻新方案已形成并完成源码核对，功能改造、数据迁移和上线验收尚未执行。

依据任务[计费模式你打算怎么做？汇报给我，要想保持现在的模式不变，新增解决](codex://threads/01a0b591-94e7-77a3-b1d0-81ae84035556)最后一轮方案，采用“New API 负责账号、模型权限与扣费，Canvas 负责创作、调用、任务和素材”的路线。本文替代原模型调用恢复计划；旧文档按本轮要求删除。历史计费方案和检查点保留为实现及迁移依据，不再作为新功能的建设目标。

## 1. 目标与范围

用户在画布连接自己的 New API 账号，完成授权后，系统为其可用分组创建或复用名称以 `Canvas` 开头的 Key。画布按“账号、分组、模型”提供选择，生成请求固定使用该用户所选分组的 Key，费用仅按 New API 的实际规则处理。

| 内容             | 翻新后的行为                                                                       |
| ---------------- | ---------------------------------------------------------------------------------- |
| 账号             | 保留 Canvas 的项目和资源身份，新增与 New API 账号的授权关联；不保存 New API 密码   |
| Key              | 服务端自动管理本人可用分组的 Key，按令牌 ID 和授权归属识别，密文保存               |
| 模型             | 从所选 Key 的鉴权目录读取，使用已有协议适配；无需在 Canvas 再上架商品              |
| 收费             | 新任务由 New API 按用户、分组、模型和实际用量扣费；Canvas 不再充值、冻结或扣第二笔 |
| 广场、充值、账单 | 打开对应 New API 页面；停止 Canvas 的售价编辑、价格草稿写回及广场复制维护          |
| 创作与执行       | 保留节点、工作流、多 Key 选择、连接删除、安全尾号、输入校验、任务查询和素材归档    |
| 历史数据         | 保留项目、资产、原凭据版本、模型绑定和账务；旧任务按原记录收尾                     |

从当前代码定向解耦，不整条回退收费分支。收费阶段新增的连接管理、视频修复、冻结输入、幂等提交和恢复能力必须保留。

本轮交付仅为新计划、旧文档删除和关联 TODO 更新。后续实施优先 PC Web；移动端、其他身份提供方、支付系统、新供应商协议、历史账务清库及性能重构不属于本任务。

### 完成标准

- 用户 A、B 分别授权后，只能查看和使用各自的分组 Key；重复登录、刷新、并发回调不重复建 Key。
- 普通生成、批量、工作流、重试、优化和反推使用所选用户凭据，无 Canvas 上架、报价或钱包前置门槛。
- 新模式任务不创建 Canvas 报价、冻结、扣款或退款；New API 收费归属于实际授权账号，历史任务不重复收费。
- 精确模型和输入组合分别完成验证，至少覆盖既有文字、图片流程与 `MiniMax-H3`、`wan3.0-video`、`wan3.0-video-prime` 的拟开放组合。
- 旧项目可以打开，提示词、素材、参数和历史结果保留；无法确认原调用身份时要求重新选择，不能自动换 Key。
- 数据副本迁移、账号隔离、故障恢复、PC Web 烟测及受影响检查通过后，才进入配套上线和获授权的真实调用验收。

“自动导入 Key”“目录可见”“本地适配通过”和“真实调用成功”分别记录。连接成功不代表所有模型已经适配。

## 3. 账号授权与分组 Key

### 3.1 已有接口与缺口

以下是 New API 当前源码中的接口，不表示 Canvas 已接入，也不代表生产部署已具备相同版本。

| 现有接口                                | 能力与限制                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------------- |
| `GET /api/user/self/groups`             | 经用户鉴权读取可用分组；不能用公开旧接口 `/api/user/groups` 代替本人权限               |
| `POST /api/token/`                      | 创建令牌，但只返回成功信息，不返回令牌 ID 或完整 Key                                   |
| `GET /api/token/`、`GET /api/token/:id` | 查询本人令牌；Key 为脱敏值；名称不是唯一约束                                           |
| `POST /api/token/:id/key`               | 按当前用户身份读取指定令牌的完整 Key，不能作为公开前端接口转发                         |
| `GET /v1/models`                        | 按 Key 读取可见模型，包含 `supported_endpoint_types`；不完整描述 Canvas 合同和输入能力 |
| `GET /v1/canvas/catalog`                | 已有桥接目录，按 Key 的分组、模型限制与可用渠道过滤；仍需校验协议和能力声明            |
| `POST /v1/canvas/estimate`              | 已有上游估算入口，可以作为参考费用来源，不等于价格锁定或实际扣款                       |
| `GET /v1/canvas/receipts/:requestId`    | 按用户、令牌 ID 和请求 ID 读取回执；新建令牌不能读取旧令牌的回执                       |

`/v1/canvas/*` 受 `CANVAS_BRIDGE_ENABLED` 控制，默认关闭，关闭时返回 404。桥接不可用不能伪装成空目录、免费调用或账号无模型。可见模型由鉴权目录决定；能否执行还要有已确认的适配合同，不能按模型名称或端点类型猜测。

`supported_endpoint_types` 还是按模型名全局聚合的数据，不是该 Key 的逐渠道能力证明。读取模型目录也受 Key 状态和额度校验；零额度且非无限额度、过期或禁用可能直接返回鉴权失败，不能解释为空目录或偷偷换 Key。回执接口对过期/耗尽有单独处理，但禁用或删除 Key 后仍不可读，不能把它的规则外推到目录或视频查询接口。

目录的 `available` / `unavailable_reason` 需要按原因处理。当前桥接的 `missing_pricing` 表示没有同时满足支持与定价的候选路由，媒体能力也受定价筛选影响，不能把它全部当成“只是没有参考价”而放行。阶段 A 固定上游“调用资格与参考估算状态”的合同，区分账号权限、可用路由、适配合同、输入支持与参考费用：前四项缺失或不明时阻止提交；已有独立调用依据、仅参考估算未知时不再增加 Canvas 报价门槛。Canvas 不得擅自重解释当前 `available: false`；New API 明确拒绝受理的状态不能改成可用，缺证据时也不能猜测免费或任意执行。

接口证据固定在上述 New API 提交：[用户及令牌路由](https://github.com/lysimportant/forknewapi/blob/43ee5dbf99ac6dd194e99f298ec582cf3adedd46/router/api-router.go)、[令牌实现](https://github.com/lysimportant/forknewapi/blob/43ee5dbf99ac6dd194e99f298ec582cf3adedd46/controller/token.go)、[桥接目录](https://github.com/lysimportant/forknewapi/blob/43ee5dbf99ac6dd194e99f298ec582cf3adedd46/controller/canvas_bridge.go)和[回执鉴权](https://github.com/lysimportant/forknewapi/blob/43ee5dbf99ac6dd194e99f298ec582cf3adedd46/controller/canvas_receipt.go)。这些链接用于定位本轮核对的源码，不证明生产状态。

现有后台用户接口接受 dashboard JWT 或 PAT；New API 的 OAuth 登录是它作为第三方登录客户端，不等于它已经能向 Canvas 签发授权。需要新增账号授权桥接和幂等分组令牌管理。本文不把拟新增接口命名成现成能力，正式路径、请求体、scope 与错误码在阶段 A 固定并写入接口文档。

### 3.2 推荐授权流程

1. 用户先以 Canvas 身份进入设置，点击“连接 New API 账号”。Canvas 服务端建立一次性授权事务，绑定当前用户、可信 New API 站点和精确回调地址。
2. 浏览器跳转 New API，由 New API 完成登录、二次验证与授权展示。说明关联账号、拟创建的分组令牌、期限和额度策略；Canvas 不接收账号密码。
3. New API 返回短时、一次性授权码。回调验证 `state`、PKCE、回调地址及发起会话，后台兑换有限权限授权。URL、浏览器存储和前端响应不携带长期 Key、PAT 或 dashboard JWT。
4. 用发行站点与 New API 不可变用户 ID 建立关联，不以用户名或邮箱自动合并用户。首次关联不得赋予 Canvas 管理员权限；同一站点账号默认只绑定一个 Canvas 用户。
5. 授权仅允许读取本人身份/分组及管理本 Canvas 实例创建的令牌；不得获得其他令牌、价格或站点管理权限。刷新、过期、撤销和换账号必须有明确状态与接口合同。
6. 获取可用分组，幂等准备令牌并加密保存；按组返回成功或失败，成功组可用，失败组允许恢复。授权取消、回调重放或账号切换不能留下可供另一用户使用的连接。

Canvas 自身仍负责项目、素材和任务权限。首期不替换整个 Canvas 登录系统；“使用 New API 一键登录 Canvas”如需实现，必须复用上述稳定身份映射，另行验证旧账号归属，不自动合并历史用户。

受限授权由新增桥接处理器验证 issuer、client、instance、grant 和 scope。现有 `/api/token/*` 可管理该用户全部令牌，不能直接透传该接口并宣称已经做到实例隔离。授权续期、撤销与派生 Key 的生效关系必须明确：撤销 grant 本身不会使既有模型 Key 自动失效，需要同时限制本地新执行及按合同撤销远端派生令牌。

### 3.3 自动创建与恢复

- 命名采用 `Canvas-实例标识-分组标识`，例如 `Canvas-main-default`。`Canvas` 是令牌名称前缀，实际 Key 由 New API 生成。当前名称上限为 50 个 UTF-8 字节，需生成稳定短名并处理截断碰撞；原始分组 ID 独立保存，不从显示名称反推身份。
- 幂等身份为“Canvas 实例、New API 用户 ID、实际分组 ID”。New API 服务端在事务和唯一约束内创建/复用，并持久化令牌 ID；Canvas 保存对应管理关系。重复授权、回调和并发同步返回同一有效关联。
- 现有 `POST /api/token/` 不具备上述幂等合同。不能用“查同名后创建”模拟原子操作，也不能凭 `Canvas` 前缀接管手工创建的令牌。必须先补齐上游幂等管理，再开放自动创建。
- 创建结果不明时，用原操作身份查询 New API 管理记录后继续取回原结果；不能直接补发创建请求。同一操作 ID 携带不同参数时拒绝。上游已建、本地未落库时允许恢复同一令牌，不能永久遗留无主 Key。
- 默认为用户有权使用的实际分组建立独立令牌，不开启跨组自动回退。`auto` 是路由组，不代表全部实际分组；首期不自动为它另建 Key。确需启用时单独确认路由范围和收费归属，必须传非空的显式 `auto_groups`；省略、`null` 或空数组会继承管理员全局 Auto。指定范围失权后为空则不可用，不回退全局范围。
- 令牌权限不得超过当前账号权限，创建时和运行时均检查分组资格。期限、额度、模型限制及跨组重试字段显式赋值，按已确认策略在授权时说明；不默认创建永久且无限额度的令牌。非无限额度且剩余额度为零的 Key 不能完成目录接入，应展示原因并让用户调整策略，不擅自提升额度。余额或套餐适用范围以 New API 为准，不承诺所有分组共用所有套餐。
- 新增分组可在已有授权范围内同步；分组撤销、Key 过期或用户在 New API 删除 Key 后，连接标为不可用，保留历史任务引用。显式撤销后不能靠后台刷新自动重建权限。
- “断开账号”立即禁止新提交，取消尚未发送节点的执行资格，保留原任务 ID。远端撤销仅处理已记录归属的令牌，不删除用户其他 Key；已发送任务可能因撤销无法继续查询，必须提示并保留待处理状态。
- Key 轮换建立新凭据版本，新任务用新版本；旧任务保留原版本和上游令牌 ID 引用。回执不能跨令牌读取，正常轮换应先安排旧任务与回执收尾；用户主动撤销则立即生效并明确哪些在途操作受阻，不为收尾拖延撤销。失效 Key 不保证可查询，也不改用其他 Key 重发任务。

## 4. 用户隔离与调用身份

优先复用 `AiCredential`、`ModelCatalog`、凭据加密、版本和 `Run`，补充两类持久关系：Canvas 用户到 New API 账号的关联，以及账号/实例/分组到 New API 令牌 ID 的关联。具体表名在阶段 A 确认，不复制第二套模型平台。

| 关系     | 必须保存或校验的语义                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------ |
| 账号关联 | Canvas 用户、规范化发行站点、New API 用户 ID、授权范围/状态/有效期；同一上游身份不可被另一用户静默认领 |
| 分组令牌 | 账号关联、稳定实例 ID、原分组 ID、上游令牌 ID、本地凭据与版本、幂等操作身份和同步状态                  |
| 模型目录 | 按用户连接及凭据版本读取，保留精确模型 ID、合同、能力来源和刷新时间；缓存不能跨用户复用                |
| 执行快照 | 提交者、项目、逐节点凭据版本、精确模型、协议、冻结素材、参数、执行授权及收费责任模式                   |

浏览器仅获得连接公开身份、分组、主机和安全 Key 尾号。完整 Key 与授权凭据继续使用服务端密文存储，日志、错误、导出和测试夹具不得包含真实值。受信站点必须由部署配置约束，不能接受任意外部回调或利用基址访问内网。

权限检查覆盖列表、详情、刷新、默认模型、创建任务、重试、轮询、下载和 Worker 读取。前端隐藏他人连接不能代替服务端校验；管理员也不能因历史平台连接入口而读出用户私人 Key。

旧 `ownerId: null` 的共享连接保留为迁移对象及旧任务凭据，不自动复制给所有用户，也不成为新用户无连接时的回退。项目模型默认属于旧共享凭据时展示待重选；共享项目的后续执行也必须校验当前执行者的个人授权。

### 新请求链路

```text
Canvas 用户会话
  → 本人已授权账号及分组连接
  → 按该 Key 读取目录并解析精确模型、合同与输入能力
  → 校验项目/素材权限，冻结逐节点输入及凭据版本
  → 原子持久化执行授权、Run 与 outbox
  → Worker 校验持久授权后，以冻结 Key 向 New API 提交
  → New API 路由与扣费
  → 保存原任务身份，查询、下载并归档结果
```

普通生成、批量、DAG、重试、提示词优化、反推及默认模型走同一套身份解析。不能只修节点生成按钮，留下优化/反推使用全局管理员 Key。

## 5. 计费解耦与任务恢复

### 5.1 新旧任务分流

收费责任模式由服务端在受理任务时持久化，客户端不能通过提交一个开关来选择是否付 Canvas 费用。

| 任务类别                           | 执行与收费规则                                                           |
| ---------------------------------- | ------------------------------------------------------------------------ |
| 切换前已受理、存在 Canvas 冻结账务 | 按原快照、Key、确认上限及账务合同完成或核实；不得重新创建上游任务        |
| 切换后新受理的 New API 账号任务    | 校验本人执行授权，费用归 New API；不创建 Canvas 报价、冻结、扣款或退款   |
| 旧版本非计费历史任务               | 继续依现有历史豁免证据处理，不补收费用，也不把缺字段一概认成新模式       |
| 只有旧报价、尚未受理的请求         | 切换后拒绝消费旧报价并提示刷新；必须明确展示新收费方式，再由用户重新发起 |

新模式不保留“确认最高金额、超出由 Canvas 承担”的承诺。可选费用提示仅来自 New API，标明估算、时间、币种/单位和可能变化；余额显示同样不构成冻结。估算未知或失败显示“费用暂不可预估”，不当成免费，不要求回到 Canvas 钱包。实际可否受理由 New API 权限、额度和协议决定。

不接 Canvas 真实支付、不新建定价公式，也不把旧 Canvas 余额自动转换成 New API 余额。旧钱包余额及未结算事项先保留并核对，迁移或退款属于独立资金处理。所有在途事项关闭后，历史账务转为只读；收尾期间兼容处理器仍可按原合同写入必要的结算、释放与核实结果。

### 5.2 执行授权不能随钱包删除

- 从现有提交事务中分离“有权执行”的证据。新任务原子写入用户/项目/逐节点授权、不可变快照、Run 和 outbox；数据库与 Redis 之间继续可靠投递。
- Worker 从持久记录读回授权并验证快照、用户、原凭据版本和收费责任模式，不信任队列消息自带的 `userId` 或模式标记。未授权、快照冲突、连接撤销或归属不符在供应商 POST 前失败。
- 幂等键按原请求归属验证。同一项目下另一用户不能凭猜中的幂等键接管已有任务；取消、重试和恢复同样检查权限。
- 发送意图、原请求 ID、上游任务 ID 和结果归档独立于账务存在。提交超时且结果未知时，保留待核实并查询已有身份；没有供应商幂等保证时不自动重发可能扣费的 POST。
- 断线或进程重启恢复已发送项时继续轮询。DAG 中尚未发送的下游节点可在原执行授权仍有效时首次发送；账号撤销后停止这些新发送。
- 本地取消不推断供应商已取消或退款；只有确认的远端合同允许远程取消。收费状态以 New API 实际记录为准，缺少可靠回执保持未知。

## 6. 模型、素材和旧项目迁移

1. **模型选择不再依赖商品发布。** 用本人分组 Key 的目录解析精确模型、媒体类型和协议；同名模型按账号与分组区分。不从公开广场或价格推断可调用权限，不自动改用其他 Key。
2. **保留已确认映射。** `MiniMax-H3 → h3` 沿用 New API 原渠道配置；Canvas 保留所选对外精确模型 ID。大小写、版本、按次后缀和 URL/端点字段不能擅自修改。
3. **能力逐模型核对。** `/v1/canvas/catalog` 可复用，但不是所有模型通用保证。显式能力限制继续校验；缺省能力不直接等同全支持或全拒绝，沿用现有校验语义并依据实际 Provider 映射决定能否开放。
4. **H3/Wan 单独验收。** 分别核对文字、图片提及、首帧、首尾帧及拟开放参考素材。共享模型 ID 可能对应不同插件/渠道，不能拿 H3 的规则套 Wan，也不能把一个入口通过当成所有入口通过。
5. **素材仍需外部可读。** 要求 URL 的合同必须能读取同一冻结版本。检查 `MC_S3_PROVIDER_ENDPOINT` 到 Worker `S3_PROVIDER_ENDPOINT` 的实际配置、HTTPS、签名时效及外部 GET；`localhost`、容器地址或浏览器可见不等于供应商可读。
6. **旧节点通过副本迁移。** 有 `platformModelId` 时先从历史绑定找出原精确模型、连接、协议和媒体类型。只有新个人连接归属已确认、匹配唯一并符合权限时才形成替换建议；管理员共享连接不能自动归属个人。
7. **不改历史运行。** 项目副本迁移与运行快照分开；保留提示词、素材、参数、结果和节点位置。原连接缺失、同名歧义、权限不足或协议不明时标明具体原因并要求重选。
8. **默认配置同步处理。** 节点选择、项目默认、全局默认、优化/反推配置及导入导出都纳入迁移；导出不得包含个人 Key，导入不可直接认领导出方凭据。

验收记录以“精确模型、分组连接、合同、输入组合”为单位。新增未适配协议列入后置待办，不能为了让选择器可点而绕过输入预检。

## 7. PC Web 入口

- 设置页新增“New API 账号”：展示关联身份、授权状态、可用分组、Key 安全尾号、上次同步时间及每组错误；提供连接、重新授权、刷新与断开入口。
- 模型选择器按账号/分组展示实际目录。无权限、过期、协议未适配、同步失败分别提示；刷新失败保留旧数据并标注过期，不宣称本次已更新。
- 新生成流程取消 Canvas 钱包报价弹窗、冻结余额和“最高 ¥…”按钮。切换提示清楚说明由 New API 实际扣费；可选估算不能阻塞成另一套本地计费门槛。

- 原模型编辑、上架、价格草稿与钱包充值入口退出新流程；后端对应写接口同步停用，不能只隐藏按钮。移除源码在兼容收尾后进行，保留必要版权与许可声明。

账号、凭据、Run/outbox 和迁移必须有真实隔离 PostgreSQL/Redis 集成证据；沿用[隔离设施脚本](../scripts/verify-isolated.ps1)与项目 `test:integration`，配置独立 `TEST_*` 及对象前缀。New API 遵守其仓库要求执行测试、vet、构建和 Web 检查；若新增数据库关系或唯一约束，覆盖 SQLite、MySQL、PostgreSQL，不能只凭默认 SQLite 宣称三库通过。

真实生成按已明确的模型、组合、账号、费用范围和次数执行。普通自然语言提示词按当前约定先译为英文，精确模型、参数、代码及语言本身有意义的用户内容保持原值。保留请求/任务 ID 和发送次数，响应不明时恢复查询，不重复付费创建。

测试状态分为未执行、隔离通过、运行环境通过、真实调用通过或受阻。skip/pending 不算通过；记录双方版本、环境、时间、精确模型/合同、脱敏连接身份、预期与实际结果，不记录完整 Key、授权码、签名 URL 或用户素材正文。

## 10. 数据影响、发布与回退

这是后续跨模块、跨仓库、涉及持久格式和收费责任的改造，实施按大变更交付。本文档替换本身不执行迁移、不更改 New API、不改变线上计费。

1. **先备份与演练。** 记录数据库、资产、加密密钥及双方镜像/提交的恢复点，在隔离副本验证可读与恢复。账务、在途任务、待派发 outbox、Key 归属及项目引用形成脱敏清单，凭据备份不得进仓库。
2. **加法迁移。** 先增加账号关系、用户隔离和执行模式的必要结构；不删钱包、报价、绑定、流水或历史密文。迁移前后核对数量与约束，演练部分失败、重复执行和旧数据缺项。
3. **先部署兼容消费者。** New API 先具备已确认授权/幂等接口，Canvas Worker 先能识别新旧任务，API/Web 再配套更新；旧 Worker 不得领取无法解释的新模式任务。通过明确的版本门槛或队列隔离落实，不能仅靠部署顺序假定安全。
4. **再切换新提交。** 先在隔离环境验证个人账号流程，关闭旧新建报价/充值/改价写入口，再启用新模式。已受理旧任务按原规则收尾；尚未受理的旧页面请求拒绝并提示刷新。
5. **失败停止扩散。** 身份串用、模式不一致、重复创建、重复扣费或任务不可恢复时停止相关新提交，保留原任务和证据。不能通过清库、重发生成或替换全局 Key 消除表象。
6. **回退保留新事实。** 停止新增后回退 Web/API 到已验证兼容版本；保留能够处理新旧快照的 Worker 完成在途任务。旧镜像不能解释新授权时不得接管，必要时保留新 Worker 仅用于收尾。
7. **不回灌旧账务。** 不用旧数据库覆盖新增任务、授权关系和流水，不因回退撤销所有 `Canvas` 名称的 Key。远端已撤销令牌不能通过还原数据库恢复；重新授权需使用正常流程。

生产部署、真实付费调用及数据删除按用户明确授权执行。先完成代码、测试、迁移演练和可审阅发布包，再处理需要确认的最终操作；等待生产授权不阻止本地实施和准备。
