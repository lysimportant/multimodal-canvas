## 1. 目标与范围

用户点击“使用 New API 登录”，由 New API 完成身份验证后返回画布。Canvas 自动建立内部资源归属记录，为当前账号有权限使用的全部 New API 分组各创建或复用一个名称以 `Canvas` 开头的 Key，唯一明确排除“神秘分组”；上游向该账号开放的 `auto` 也纳入，并排除其通向“神秘分组”的路由。首次同步即准备全部纳入组，不等用户选中某个模型才建 Key；用户在画布自行选择“分组＋模型”，由服务端使用对应 Key 调用。每次登录、恢复会话及生成前校验纳入范围的权限，费用按 New API 实际规则处理。

这里自动创建的是各分组的 Key，不是新增 New API 分组。自动接入集合为“当前登录账号的可用分组集合减去原始分组标识精确等于 `神秘分组` 的项”，不包括该账号无权使用的站点分组；下文“全部纳入组”均指此集合。同一账号在同一 Canvas 实例内每组正常只创建一次，后续登录复用原令牌；新增纳入组才补建，模型数量或选择变化不增加 Key。

“神秘分组”不自动建 Key、不检查其 Key 状态、不查询该组模型目录，也不进入 Canvas 的自动模型列表。读取一次本人可用组清单以确定接入集合不属于单独检查该组；命中排除项后不再发该组的令牌详情、完整 Key、目录或生成验证请求。已有该组 Key 不因这条规则被删除、禁用或改组。

| 内容             | 翻新后的行为                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| 账号             | New API 是唯一登录身份；取消 Canvas 独立注册、密码登录、找回密码和邮箱验证，内部用户记录自动建立      |
| 资源             | 项目、素材、任务、生成结果和个人设置归属“New API 站点＋不可变用户 ID”；文件仍由 Canvas 存储           |
| Key              | 除“神秘分组”外，本人全部纳入组各一个 Canvas 管理 Key，首次自动准备、后续复用；排除组不创建或检查      |
| 模型             | 分组逐个读取 Key 的实际目录，再合并为保留分组身份的列表供用户选；同组模型共用 Key，排除组不加载       |
| 收费             | 新任务由 New API 按用户、分组、模型和实际用量扣费；Canvas 不再充值、冻结或扣第二笔                    |
| 广场、充值、账单 | 删除 Canvas 旧广场、上架与定价写接口；需要查看时打开对应 New API 页面                                 |
| 创作与执行       | 保留节点、工作流、按分组区分的模型选择、输入校验、任务查询和素材归档；删除手动 Key 选择与连接增删入口 |
| 测试数据         | 明确 Canvas 测试账号及关联数据清理清单，处理在途任务后清理；不触及 New API 的真实用户、余额和账单     |

从当前代码定向解耦，不整条回退收费分支。保留视频修复、冻结输入、幂等提交、恢复及服务端凭据加密/分组映射；手动填写地址、导入或选择 Key、激活全局连接、连接删除和普通界面的 Key 尾号退出新版产品流程。用户选择带分组标识的模型，系统自动使用该组 Key。

本次按用户后续授权实施 B0—B6，并允许修改 New API、创建独立 Docker 管理员和分组。PC Web 优先；生产操作、未列清单的共享数据删除和真实付费生成不属于本次自动执行范围。移动端扩展、其他身份提供方、新支付系统和性能重构后置。

### 完成标准

- 用户仅凭 New API 登录即可创建项目；A、B 的项目、素材、任务、设置和 Key 隔离，切换账号不显示上一账号的数据。
- 首次登录为本人全部纳入组各准备一个 Key，无需逐组手工导入；重复登录、恢复会话、刷新和并发回调复用同一令牌。新增组只补建该组，换模型不新建 Key；分组同步失败逐组显示，成功组可用。“神秘分组”的自动创建、Key 检查和目录请求次数为零，已有 Key 不变。
- 同一 Key 从 G1 改到 G2，或账号/分组/模型权限变化后，旧节点可保留 G1 选择并标记失效，但不能显示为仍可调用；尚未受理的任务不能静默改用 G2。上游以受理时权威状态校验预期分组，不一致时在预扣和供应商 POST 前拒绝。
- 普通生成、批量、工作流、重试、优化和反推使用所选用户凭据，无 Canvas 上架、报价或钱包前置门槛。
- 普通用户只选择“模型＋所属分组”，不再出现手动地址/Key 表单、多 Key 选择器、连接新增/激活/删除按钮或 Key 尾号；服务端仍按用户和分组绑定正确 Key，旧管理写接口同步退出。
- 新模式任务不创建 Canvas 报价、冻结、扣款或退款；New API 收费归属于实际授权账号，历史任务不重复收费。
- 精确模型和输入组合分别完成验证，至少覆盖既有文字、图片流程与 `MiniMax-H3`、`wan3.0-video`、`wan3.0-video-prime` 的拟开放组合。
- 指定测试账号及关联数据可按清单清理，清理后无失主资源、存活旧会话或可重新执行的旧队列；明确保留的项目才做归属转换，不自动分配给首次登录者。
- 内部身份结构迁移、测试数据清理演练、账号隔离、故障恢复、PC Web 烟测及受影响检查通过后，才进入配套上线和获授权的真实调用验收。

“自动导入 Key”“目录可见”“本地适配通过”和“真实调用成功”分别记录。连接成功不代表所有模型已经适配。

## 3. 账号授权与分组 Key

### 3.1 已有接口与缺口

以下是改造前已有接口，供说明复用边界；新增账号合同见本节末尾。源码和本地验收不代表生产已部署相同版本。

| 现有接口                                | 能力与限制                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------------- |
| `GET /api/user/self/groups`             | 经用户鉴权读取可用分组；不能用公开旧接口 `/api/user/groups` 代替本人权限               |
| `POST /api/token/`                      | 创建令牌，但只返回成功信息，不返回令牌 ID 或完整 Key                                   |
| `GET /api/token/`、`GET /api/token/:id` | 查询本人令牌；Key 为脱敏值；名称不是唯一约束                                           |
| `POST /api/token/:id/key`               | 按当前用户身份读取指定令牌的完整 Key，不能作为公开前端接口转发                         |
| `GET /v1/models`                        | 按 Key 读取可见模型，包含 `supported_endpoint_types`；不完整描述 Canvas 合同和输入能力 |
| `GET /v1/canvas/catalog`                | 已有桥接目录，按 Key 的分组、模型限制与可用渠道过滤；仍需校验协议和能力声明            |
| `POST /v1/canvas/estimate`              | 已有上游估算入口，可以作为参考费用来源，不等于价格锁定或实际扣款                       |
| `GET /v1/canvas/receipts/:requestId`    | 按用户、令牌 ID 和请求 ID 读取回执；新建令牌不能读取旧令牌的回执                       |

`/v1/canvas/*` 受 `CANVAS_BRIDGE_ENABLED` 控制，默认关闭，关闭时返回 404。桥接不可用不能伪装成空目录、免费调用或账号无模型。可见模型由鉴权目录决定；能否执行还要有已确认的适配合同，不能按模型名称或端点类型猜测。

`supported_endpoint_types` 还是按模型名全局聚合的数据，不是该 Key 的逐渠道能力证明。读取模型目录也受 Key 状态和额度校验；零额度且非无限额度、过期或禁用可能直接返回鉴权失败，不能解释为空目录或偷偷换 Key。回执接口对过期/耗尽有单独处理，但禁用或删除 Key 后仍不可读，不能把它的规则外推到目录或视频查询接口。

目录的 `available` / `unavailable_reason` 需要按原因处理。当前桥接的 `missing_pricing` 表示没有同时满足支持与定价的候选路由，媒体能力也受定价筛选影响，不能把它全部当成“只是没有参考价”而放行。B0 固定上游“调用资格与参考估算状态”的合同，区分账号权限、可用路由、适配合同、输入支持与参考费用：前四项缺失或不明时阻止提交；已有独立调用依据、仅参考估算未知时不再增加 Canvas 报价门槛。Canvas 不得擅自重解释当前 `available: false`；New API 明确拒绝受理的状态不能改成可用，缺证据时也不能猜测免费或任意执行。

接口证据固定在上述 New API 提交：[用户及令牌路由](https://github.com/lysimportant/forknewapi/blob/43ee5dbf99ac6dd194e99f298ec582cf3adedd46/router/api-router.go)、[令牌实现](https://github.com/lysimportant/forknewapi/blob/43ee5dbf99ac6dd194e99f298ec582cf3adedd46/controller/token.go)、[桥接目录](https://github.com/lysimportant/forknewapi/blob/43ee5dbf99ac6dd194e99f298ec582cf3adedd46/controller/canvas_bridge.go)和[回执鉴权](https://github.com/lysimportant/forknewapi/blob/43ee5dbf99ac6dd194e99f298ec582cf3adedd46/controller/canvas_receipt.go)。这些链接用于定位本轮核对的源码，不证明生产状态。

此次新增 `GET/POST /api/canvas/authorize`、`POST /api/canvas/token`、`GET /api/canvas/account`、`PUT /api/canvas/groups/:group` 和 `POST /api/canvas/revoke`，使用固定实例、精确回调和 S256 PKCE。正式请求体、scope、权限修订及错误码记录在配套 New API 仓库 `docs/authentication.md` 的 Canvas 账号接入合同章节；Canvas 继续用各组 Key 读取 `/v1/canvas/catalog`。

### 3.2 一体化登录与后台身份校验

1. Canvas 登录页仅提供“使用 New API 登录”。服务端建立一次性登录事务，绑定发起浏览器的临时会话、可信 New API 站点、实例和精确回调地址；不要求已有 Canvas 账号。
2. 浏览器跳转 New API，由 New API 完成登录和既有二次验证。按用户最新确认，Canvas 与 New API 是受信的一体化应用：登录后直接同步分组并进入画布，不再出现额外授权确认或绑定操作；Canvas 不接收账号密码。部署方启用固定客户端/实例即建立信任，服务端仍校验精确回调和 PKCE，不能自动接入任意第三方客户端。
3. New API 返回短时、一次性授权码。回调验证 `state`、PKCE、回调地址及发起浏览器事务，后台兑换有限权限授权与已验证的账号身份。登录事务用后失效并轮换 Canvas 会话，URL、浏览器存储和前端响应不携带长期 Key、PAT 或 dashboard JWT。
4. 按“规范化发行站点＋New API 不可变用户 ID”查找或原子创建内部 UUID 用户记录，用于资源外键和 Canvas 会话。用户名、邮箱、分组和 Key 不参与身份合并；回调不能指定其他资源主人，也不自动继承旧测试账号。
5. 授权仅允许读取本人身份/分组及管理本 Canvas 实例创建的令牌；不得获得其他令牌、价格或站点管理权限。刷新、过期、撤销和换账号必须有明确状态与接口合同。
6. 完成身份验证后执行第 3.4 节同步，再进入工作区。零个可用组或某组同步失败时，用户仍可在有效资源访问权限下打开自己的作品，受影响生成入口显示明确原因。仅主动切换账号时显示账号选择；换号登录后直接回画布。取消登录须验证并消费本人事务、清临时 Cookie 并返回可恢复页面，不撤销既有作品会话。回调重放或账号切换不能留下可供另一用户使用的连接。

Canvas 只保留应用会话和资源权限，不再维护另一套用户密码、注册、密码重置或邮箱验证。New API 返回的邮箱可缺省或变更，需同步调整现有必填/唯一邮箱约束及前端 DTO，不能用假邮箱满足旧代码。资料显示跟随上游身份，Canvas 专属偏好留在内部记录；管理员名单由受控配置映射到外部身份，不按首次登录或客户端声称的角色自动提升权限。

受限授权由新增桥接处理器验证 issuer、client、instance、grant 和 scope。现有 `/api/token/*` 可管理该用户全部令牌，不能直接透传该接口并宣称已经做到实例隔离。授权续期、撤销与派生 Key 的生效关系必须明确：撤销 grant 本身不会使既有模型 Key 自动失效，需要同时限制本地新执行及按合同撤销远端派生令牌。

### 3.3 自动创建与恢复

- 命名采用 `Canvas-实例标识-分组标识`，例如 `Canvas-main-default`。`Canvas` 是令牌名称前缀，实际 Key 由 New API 生成。当前名称上限为 50 个 UTF-8 字节，需生成稳定短名并处理截断碰撞；原始分组 ID 独立保存，不从显示名称反推身份。
- 先从本人可用组集合排除精确标识 `神秘分组`，再逐组创建、检查和同步；不能以显示名称模糊匹配，也不能将分组名翻译后匹配。幂等身份为“New API 站点、Canvas 实例、New API 用户 ID、分组标识”，`auto` 同样是独立关系。上游通过事务和唯一约束创建/复用并持久化令牌 ID；首次授权遍历全部纳入组，重复登录、回调和同步复用原令牌，不按节点或模型重复创建。
- 现有 `POST /api/token/` 不具备上述幂等合同。不能用“查同名后创建”模拟原子操作，也不能凭 `Canvas` 前缀接管手工创建的令牌。必须先补齐上游幂等管理，再开放自动创建。
- 创建结果不明时，用原操作身份查询 New API 管理记录后继续取回原结果；不能直接补发创建请求。同一操作 ID 携带不同参数时拒绝。上游已建、本地未落库时允许恢复同一令牌，不能永久遗留无主 Key。
- 纳入集合的普通分组与 `auto` 均自动准备各自 Key，不用一个 `auto` Key 替代其他分组。普通组固定使用该组，不开启跨组自动回退。`auto` 在界面标为“自动路由”，范围为 New API 当前给该用户解析的有序 Auto 范围再剔除 `神秘分组`。排除必须在上游目录取模型和选择执行路由前生效，不能仅隐藏前端名称；B0 固定这项新增 Canvas 接入合同，当前普通 Auto 接口不能直接保证它。
- 现有 `auto_groups` 省略、`null` 或空数组表示继承管理员 Auto 配置并过滤本人权限，不能将过滤后的空集合发成空数组，否则会重新继承全局范围。已有非空显式范围不被 Canvas 静默覆盖；写入受 `max_count` 限制，运行时还会按当前权限和上限过滤，必须读回有效有序范围，不能假定原数组仍全部生效。排除后为空、无法完整表达合法范围或上游不能强制排除时，保留该组状态并提示不可调用，不回退全局范围、不自动扩大范围；其他普通组继续正常同步。
- 令牌权限不得超过当前账号权限，创建时和运行时均检查分组资格。期限、额度、模型限制及跨组重试字段显式赋值，按已确认策略在授权时说明；不默认创建永久且无限额度的令牌。非无限额度且剩余额度为零的 Key 不能完成目录接入，应展示原因并让用户调整策略，不擅自提升额度。余额或套餐适用范围以 New API 为准，不承诺所有分组共用所有套餐。
- 每次登录同步并复用已有有效令牌，只有新可用分组在授权范围内才补建。分组撤销、Key 过期、禁用、删除或实际分组被修改时，原连接标为不可用并保留任务引用；不能将改组后的 Key 静默换名继续用，也不在后台改回或重建来抵消用户选择。重新建立关联通过显式重新授权完成。
- “每组创建一次”指常规登录和同步不重复创建；令牌轮换或用户显式重新授权替换失效令牌是有记录的例外。分组创建失败或达到上游令牌数量上限时，保留成功组，按原幂等身份恢复失败组并显示原因；不能静默漏组或删掉用户其他令牌腾位置。
- 对 `神秘分组` 的排除在登录、恢复会话、手动刷新、失败恢复和后续后台同步中一致。已有关联只在本地标记不纳入自动接入并移除自动目录缓存，不为验证排除状态查询该组 Key，也不自动删除其远端令牌；有旧在途记录时单列人工核实，不能借同步重新发送或改用其他组。
- “撤销画布授权”使会话与授权失效，立即阻止新提交和未发送节点；保留原任务 ID。远端撤销仅处理已记录归属的令牌，不删除用户其他 Key；已发送任务可能因撤销无法继续查询，必须提示并保留待处理状态。
- Key 轮换建立新凭据版本，新任务用新版本；旧任务保留原版本和上游令牌 ID 引用。回执不能跨令牌读取，正常轮换应先安排旧任务与回执收尾；用户主动撤销则立即生效并明确哪些在途操作受阻，不为收尾拖延撤销。失效 Key 不保证可查询，也不改用其他 Key 重发任务。

### 3.4 登录、生成与受理时的一致性校验

仅验证 Key 是否可用无法发现“同一 Key 已从 G1 改到仍有权限的 G2”。登录同步、执行前复核和 New API 受理校验分别解决界面陈旧、排队期间变化和跨服务检查后的竞态，三者均需实现。

| 时机                         | 校验与更新                                                                        | 失败或变化时的行为                                                 |
| ---------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 每次登录、恢复会话或重新授权 | 从上游核对账号状态、grant、可用分组、管理令牌归属/状态/实际分组、模型限制与目录   | 身份无效不能建立会话；分组失效只阻止相应生成，旧选择不自动换组     |
| 用户刷新及目录缓存到期       | 统一读取账号/分组变化，按令牌状态和能力修订刷新受影响目录                         | 保留旧目录用于提示并标记待验证，不把超时当无模型或成功同步         |
| Canvas 受理生成前            | 只核对本次所选连接的上游令牌 ID、用户、实际分组、模型权限与输入合同，形成执行快照 | 不一致则停止提交、刷新目录并要求重选；不得自动接受另一分组或模型   |
| Worker 每个节点首次发送前    | 读回持久授权和快照，复核当前账号、令牌、分组及模型资格                            | 权限撤销或版本冲突时停止未发送项，已发送项保留原任务身份           |
| New API 受理请求时           | 依据可信状态比较预期分组及必要的权限修订，路由、预扣和提交沿用同一受理决定        | 不匹配在预扣与供应商 POST 前拒绝，不能忽略预期字段继续按新分组计费 |

新增上游合同必须覆盖令牌改组、账号禁用/所属组变化、可用组撤销、模型限制变化及可达模型/合同变化；同步返回的校验身份绑定用户、令牌和实例，浏览器不能伪造权限。权限修订表示相关授权元数据变化，不把余额递减或价格变化当作身份版本，也不提供锁价承诺。

用户选择 `auto` 时，预期分组是路由策略 `auto`，不是某个固定实际组。校验包含该令牌当前解析并排除 `神秘分组` 后的有序实际组范围及权限修订，由 New API 在受理时按所选模型从此范围决定实际组，并固定到请求与回执；不能用“`auto` 等于实际组名”的比较阻断正常路由。Canvas 管理令牌默认 `cross_group_retry: false`，不在受理后切换实际组；发现用户修改该字段时先标记配置变更，不能静默覆盖或忽略。普通组不因同名模型在别组可用而换组，`auto` 也不能绕过排除项。

两端已固定 `x-canvas-execution`：canonical、无填充 base64url UTF-8 JSON，包含 version、issuer、user_id、instance_id、grant_id、token_id、expected_group、permission_revision、auto_groups 九个字段。不能只在 Canvas 发请求前检查，也不能仅在 New API 入口比较一次陈旧缓存就声称消除竞态。上游需在权限变更与请求受理之间确定一致性边界，复用并验证已有令牌缓存失效机制；相应用户/分组/模型权限缓存也必须失效。通过事务、版本条件或同等原子机制确保受理使用权威状态，并将决定传递到本次路由、预扣和供应商发送，不在中途重新选组。变更发生在明确受理边界之后时，不追溯改变已受理任务的分组；撤销与在途任务的后续处理按原身份执行，不能承诺撤回已发送的请求。

首次使用先统一拉取分组与本人管理令牌；同一登录事务或并发刷新合并同步操作，限制并发并逐组报告。目录缓存按内部用户、凭据及版本、实际分组和权限修订隔离，只刷新失效项；没有上游修订字段时采用有期限的刷新，不能伪造版本或沿用旧成功状态。生成前校验不因为页面缓存未过期而省略。新增 Webhook/常驻推送不是首期必需条件，先完成明确的登录、刷新和受理合同。

## 4. 用户隔离与调用身份

复用内部 `User` UUID、`AiCredential`、`ModelCatalog`、凭据加密、版本和 `Run`。外部身份与内部用户一一映射，由 New API 登录自动创建，用户不需要另一套账号。补充站点/用户到内部 UUID、账号/实例/分组到令牌 ID 的关系及相关唯一约束，具体表名在 B0 确认。

| 关系     | 必须保存或校验的语义                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| 身份映射 | 规范化发行站点、New API 不可变用户 ID、内部 UUID、授权范围/状态/有效期；并发首次登录只能创建一个内部用户      |
| 资源归属 | 项目、素材/版本、上传会话、任务、生成结果和个人设置关联内部 UUID；归属来自已验证会话，不信任客户端 owner 字段 |
| 分组令牌 | 账号关联、稳定实例 ID、原分组 ID、上游令牌 ID、本地凭据与版本、幂等操作身份和同步状态                         |
| 模型目录 | 按用户、凭据及版本、实际分组、权限修订隔离，保存精确模型 ID、合同、能力来源和刷新时间                         |
| 执行快照 | 提交者、项目、逐节点凭据版本/上游令牌 ID、预期分组与权限修订、精确模型、协议、冻结素材、参数和执行授权        |

节点只保存可验证的模型、分组及后台管理关系引用，完整 Key 由 API/Worker 使用；项目导出、复制与浏览器存储不包含 Key。用户看到模型、所属分组和可用状态，不必看到或选择 Key、凭据来源地址和尾号；服务端仍验证引用是否属于当前用户。Key 与授权凭据继续使用密文存储，日志、错误和测试夹具不得包含真实值。站点地址由部署配置约束，不能接受任意外部回调或利用基址访问内网。取消手动管理界面不意味着删除内部凭据标识、版本或脱敏能力。

素材二进制继续保存在 Canvas 的对象存储，数据库通过内部用户映射确定主人；无需把文件或 Canvas 项目表迁到 New API。上游改名、换邮箱、改组或轮换 Key 不改变资源归属；同名账号删除后重建也不能自动认领旧资源。资源权限覆盖查询、上传、下载、导出、SSE/任务订阅及签名地址签发，不能只隔离模型调用。

权限检查覆盖列表、详情、刷新、默认模型、创建任务、重试、轮询、下载和 Worker 读取。前端隐藏他人连接不能代替服务端校验；管理员也不能因历史平台连接入口而读出用户私人 Key。

旧 `ownerId: null` 共享连接只用于清理盘点、指定保留数据转换或在途任务收尾，不自动复制给新用户，也不作为缺少个人 Key 的回退。待保留项目的旧默认模型标记为待重选，执行者必须使用本人的分组授权。

账号切换或退出时撤销本次 Canvas 会话，清理项目/模型缓存、内存画布、选中素材、待提交请求和任务订阅；中断旧浏览器请求，忽略迟到响应，并通知其他标签页同步退出，防止旧数据被填入新账号。旧账号已经受理的任务仍属于旧账号，后台可在授权有效时继续；新账号不能查询、接管或用自己的 Key 续发。普通退出不自动删除分组 Key。按用户最新的一体化要求，PC 不再单列“重新授权/撤销画布授权”；后台撤销仍使本地会话、未发送执行与派生权限失效，用于上游禁用及受控运维，不成为日常登录步骤。

登录或授权续期无法验证上游身份时不签发新会话。已有尚有效且未被撤销的 Canvas 会话在上游暂时不可用时可只读查看本人已保存内容，停止新生成；会话到期、账号禁用或撤销被确认后停止资源访问。已签发对象存储 URL 在过期前可能仍能访问，切换账号会清理本地引用并停止续签，不把清缓存描述成远端 URL 立即失效；时效及需要代理访问的资源在实施时明确。

### 新请求链路

```text
New API 登录与 Canvas 内部身份映射
  → 登录同步本人账号、实际分组、管理 Key 与目录
  → 生成前复核所选连接和精确模型，校验项目/素材权限
  → 冻结逐节点输入、凭据版本、预期分组及权限修订
  → 原子持久化执行授权、Run 与 outbox
  → Worker 复核持久授权与当前资格，以冻结 Key 提交
  → New API 校验预期分组及受理权限，再按同一决定路由与扣费
  → 保存原任务身份，查询、下载并归档结果
```

普通生成、批量、DAG、重试、提示词优化、反推及默认模型走同一套身份解析。不能只修节点生成按钮，留下优化/反推使用全局管理员 Key。

## 5. 计费解耦与任务恢复

### 5.1 新任务收费与旧测试任务收尾

最终新系统仅由 New API 收费，不长期维护两套账务。切换前先盘点旧测试任务：优先暂停旧提交、处理在途任务与待核实项，再切换。若确有不能在切换前完成的任务，仅对这份清单保留临时兼容处理器；模式由服务端记录，客户端不能用字段切换收费规则或启动旧路径。

| 任务类别                        | 执行与收费规则                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------- |
| 切换前已受理且仍在处理的任务    | 保留原快照、Key 和账务证据收尾；已发送项不重复 POST，未发送项按暂停/取消决定处理 |
| 切换后新受理的 New API 账号任务 | 校验本人执行授权，费用归 New API；不创建 Canvas 报价、冻结、扣款或退款           |
| 已结束、明确可清理的测试记录    | 纳入账号、项目、账务及对象清理清单，不补收费用，不为展示测试历史长期保留钱包     |
| 只有旧报价、尚未受理的请求      | 切换后拒绝消费旧报价并提示刷新；必须明确展示新收费方式，再由用户重新发起         |

新模式不保留“确认最高金额、超出由 Canvas 承担”的承诺。可选费用提示仅来自 New API，标明估算、时间、币种/单位和可能变化；余额显示同样不构成冻结。估算未知或失败显示“费用暂不可预估”，不当成免费，不要求回到 Canvas 钱包。实际可否受理由 New API 权限、额度和协议决定。

### 5.2 执行授权不能随钱包删除

- 从现有提交事务中分离“有权执行”的证据。新任务原子写入用户/项目/逐节点授权、不可变快照、Run 和 outbox；数据库与 Redis 之间继续可靠投递。
- Worker 从持久记录读回授权并验证快照、用户、原凭据版本、预期分组和权限修订，不信任队列消息自带的 `userId` 或模式标记。未授权、快照冲突、连接撤销、分组变更或归属不符在供应商 POST 前失败；临时旧任务处理器只能执行原清单内任务。
- 幂等键按原请求归属验证。同一项目下另一用户不能凭猜中的幂等键接管已有任务；取消、重试和恢复同样检查权限。
- 发送意图、原请求 ID、上游任务 ID 和结果归档独立于账务存在。提交超时且结果未知时，保留待核实并查询已有身份；没有供应商幂等保证时不自动重发可能扣费的 POST。
- 断线或进程重启恢复已发送项时继续轮询。DAG 中尚未发送的下游节点可在原执行授权仍有效时首次发送；账号撤销后停止这些新发送。
- 本地取消不推断供应商已取消或退款；只有确认的远端合同允许远程取消。收费状态以 New API 实际记录为准，缺少可靠回执保持未知。

## 6. 模型、素材和指定保留的项目

1. **模型选择不再依赖商品发布。** 用本人分组 Key 的目录解析精确模型、媒体类型和协议；同名模型按账号与分组区分。不从公开广场或价格推断可调用权限，不自动改用其他 Key。
2. **保留已确认映射。** `MiniMax-H3 → h3` 沿用 New API 原渠道配置；Canvas 保留所选对外精确模型 ID。大小写、版本、按次后缀和 URL/端点字段不能擅自修改。
3. **能力逐模型核对。** `/v1/canvas/catalog` 可复用，但不是所有模型通用保证。显式能力限制继续校验；缺省能力不直接等同全支持或全拒绝，沿用现有校验语义并依据实际 Provider 映射决定能否开放。
4. **H3/Wan 单独验收。** 分别核对文字、图片提及、首帧、首尾帧及拟开放参考素材。共享模型 ID 可能对应不同插件/渠道，不能拿 H3 的规则套 Wan，也不能把一个入口通过当成所有入口通过。
5. **素材仍需外部可读。** 要求 URL 的合同必须能读取同一冻结版本。检查 `MC_S3_PROVIDER_ENDPOINT` 到 Worker `S3_PROVIDER_ENDPOINT` 的实际配置、HTTPS、签名时效及外部 GET；`localhost`、容器地址或浏览器可见不等于供应商可读。
6. **只迁移指定保留内容。** 当前账号已确认为测试账号，不默认迁移全部旧项目。需保留的项目先列明目标 New API 身份，再在副本转换；`platformModelId` 仅用于取回原精确模型、协议和媒体类型，不能把管理员共享 Key 归给个人。
7. **转换保留原内容。** 保留项目中的提示词、素材、参数、结果和节点位置。新个人分组连接不唯一、原连接缺失或权限不符时要求重选；没有明确接收账号的资源留在隔离备份中，不变成公开或无主资源。
8. **默认配置按账号隔离。** 节点、项目默认、用户全局默认、优化/反推及导入导出同步处理；旧全站默认不得被新用户自动继承。模板可保留精确模型建议，但不携带 Key 或可直接使用的他人凭据身份。

验收记录以“精确模型、分组连接、合同、输入组合”为单位。新增未适配协议列入后置待办，不能为了让选择器可点而绕过输入预检。

## 10. 数据影响、发布与回退

本次改造跨 Canvas 与 New API，涉及身份、执行授权和前向删表迁移，按大变更交付。迁移只用于隔离环境及新 Docker 数据库；8080 入口现由独立新栈提供，旧共享 Web/API/Worker 已停止。旧共享数据仅按已核对清单清理，含 unknown 的旧库不执行删表迁移，也不把保留作品自动归给新账号。

### 10.1 测试数据清理边界

用户已允许清理当前 Canvas 测试账号；实施前把目标实例、账号 ID、关联记录数量和对象存储前缀列成可审阅清单，再按该范围执行。清单区分“删除”“明确保留并指定接收身份”“在途/待核实暂缓”；没有清点的数据不能默认全删，不能用用户名或 `Canvas` 前缀批量猜测归属。

- 清理范围包括清单内账号及旧会话、验证/重置记录、测试项目/画布、素材版本/上传会话、任务及 outbox/队列、默认设置、个人 Skill、测试钱包/报价/流水，以及不再使用的旧广场模型/价格草稿。逐项核对引用关系，不只删除 `User` 行后让 `SetNull` 资源留在系统中。
- 先暂停旧提交、旧账号注册和相关后台同步，盘点并停止未发送的测试任务；已发送且状态不明的上游任务保留原请求/任务身份查询，不能因本地清理补发。涉及真实支出或冻结的记录先核实、处理，未结项不进入删除批次。
- 明确保留的项目先在副本转换并验证目标账号；其他素材按清单删除。对象可能被共享或去重引用，清理前核对版本和其他引用，只删除不再被保留数据使用的对象。数据库与对象存储、Redis 清理分别记录结果，部分失败可恢复并支持重复执行。
- New API 的真实用户、余额、套餐、渠道和账单不在删除范围。测试用远端令牌只能按已确认的令牌 ID、用户和实例归属处理；与待收尾任务有关时先安排查询，不能按名称删除所有 `Canvas` 令牌。
- 清理后核对数量、外键、失主对象、旧会话失效、队列命名空间和后台任务，确认旧 outbox 或备份恢复不会重新投递已清理生成任务。无需为已完成清理的测试记录继续维护双账号、双钱包或历史 UI。

### 10.2 发布与回退

1. **备份并验证。** 记录数据库、对象、必要加密密钥及双方镜像/提交的恢复点，备份不进源码仓库。先在隔离副本演练清理、重复执行及恢复；Git 回退不能恢复已删除数据库记录或对象。
2. **先加必要结构。** 增加外部身份唯一约束、内部用户映射和用户凭据权限，调整邮箱及会话合同；先验证核心链路，再执行指定测试清理。旧依赖的表或字段必须等引用与在途任务处理完后才能删除。
3. **部署匹配版本。** New API 先具备登录/幂等管理及预期分组受理合同，Canvas API/Worker/Web 配套更新。通过版本门槛或队列隔离阻止旧 Worker 领取新授权任务；旧页面及旧注册/报价入口返回明确刷新提示，不回退到测试账号登录。
4. **切换与收尾。** 默认在暂停旧提交、处理旧任务后切换；确有剩余清单任务时保留受限兼容消费者，不允许从旧入口创建新任务。新用户数据单独标识，不能混入测试清理。清理完成、真实检查通过后移除无用途旧模块。
5. **故障控制。** 出现身份串用、分组不一致、重复创建/扣费或任务不可恢复时停止相关新提交并保留证据；不能用清库、重发或替换全局 Key 消除表象。
6. **代码回退。** 只回退到能理解当前身份及任务结构的版本；保留必要消费者完成在途任务。旧版本不能理解新授权或表已删除时，不能直接回退并重开旧提交，应保持维护状态并按已演练方案恢复。
7. **数据恢复。** 若需恢复测试备份，先恢复到隔离位置、禁用任务派发，核对后只恢复明确需要的数据，不覆盖切换后新用户作品、身份关系或真实账务。远端已撤销 Key 不能靠本地备份复活，也不自动重建授权。

生产操作、超出清单的删除和真实付费调用仍按对应授权执行。本地实现、检查、演练和可审阅操作包继续完成，不因尚未决定上线而停止准备。
